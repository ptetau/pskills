## Delivers

The command `wordfreq` takes the option `--top N` and prints only the N most common words. A bad N gives the error `TOP_INVALID`. The usage line ignores `--top` and its value, and a second `--top` gives the usage line.

## Requirements

### JOB-report-word-frequencies.R5 · Usage line for a wrong number of arguments

- Given no arguments, when the user runs `wordfreq`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.
- Given the arguments `a.txt b.txt`, when the user runs `wordfreq a.txt b.txt`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.
- Given the arguments `--top 2` with no file, when the user runs `wordfreq --top 2`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.

### JOB-report-word-frequencies.R7 · Print only the N most common words

- Given a file with `b a b c a b`, when the user runs `wordfreq --top 2 FILE`, then the lines are `b 3` and `a 2`, and the exit code is 0.

## Interface

The user action in each acceptance line is a run of the command. Thus, the checks must drive the command itself, in a new process. A check can call `main` for a case that needs no new process.

- Command `python3 -m wordfreq [--top N] FILE` in `wordfreq/__main__.py`
  - in: `FILE` is a path (text). `--top N` is optional, and `N` is the text that follows `--top`. The option can come before or after `FILE`.
  - out: one line `<word> <count>` for each word, most common first, on standard output. The exit code is 0.
  - with `--top N`: only the first N lines.
  - errors: `TOP_INVALID` gives `error: --top needs a whole number greater than zero` on standard error, nothing on standard output, and exit code 2.
  - errors with no code in `DES-errors`: `usage: wordfreq FILE` (the number of files is not one, or `--top` appears two times) and `error: cannot read <path>`. Both give nothing on standard output and exit code 2. A check expects the exact message and the exit code.
  - A check runs the command with the project root as the working folder, and reads standard output, standard error, and the exit code.
- `main(argv: list[str] | None = None, stdout: TextIO | None = None, stderr: TextIO | None = None) -> int` in `wordfreq/cli.py`
  - This function exists now. The command calls it. This change alters how it reads `argv`.
  - in: `argv` is the list of arguments without the program name. `stdout` and `stderr` take the place of the standard streams.
  - out: the exit code, 0 or 2. The lines and the messages go to `stdout` and `stderr`, as for the command.
  - errors: the same as for the command.
- Order of the errors: the usage line comes first (assumed), then the `TOP_INVALID` error, then the file error. Thus, `wordfreq --top 0` with no file gives the usage line.
