# CH-0001 · Top option

Intent: IN-0001 · Scope: JOB-report-word-frequencies · Status: planned · Ticket: none · Branch: none · Base: main
Tests-Locked: none

## Delivers

The command `wordfreq` takes the option `--top N` and prints only the N most common words. A bad N
gives the `TOP_INVALID` error. A second `--top` gives the usage line.

## Requirements

### JOB-report-word-frequencies.R5 · Usage line for a wrong number of arguments

- Given no arguments, when the user runs `wordfreq`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.
- Given the arguments `a.txt b.txt`, when the user runs `wordfreq a.txt b.txt`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.
- Given the arguments `--top 2` with no file, when the user runs `wordfreq --top 2`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.

### JOB-report-word-frequencies.R7 · Print only the N most common words

- Given a file with `b a b c a b`, when the user runs `wordfreq --top 2 FILE`, then the lines are `b 3` and `a 2`, and the exit code is 0.
- Given a file with `b a b c a b`, when the user runs `wordfreq FILE --top 2`, then the lines are `b 3` and `a 2`, and the exit code is 0.
- Given a file with `pear apple fig`, when the user runs `wordfreq --top 2 FILE`, then the lines are `apple 1` and `fig 1`.
- Given a file with `b a b c a b`, when the user runs `wordfreq --top 1 FILE`, then the output is `b 3`.
- Given a file with `b a b c a b`, when the user runs `wordfreq --top 10 FILE`, then the lines are `b 3`, `a 2`, `c 1`.
- Given a file with `b a b c a b`, when the user runs `wordfreq --top 03 FILE`, then the lines are `b 3`, `a 2`, `c 1`.
- Given an empty file, when the user runs `wordfreq --top 3 FILE`, then standard output is empty and the exit code is 0.
- Given any file, when the user runs `wordfreq --top 0 FILE`, then standard error is `error: --top needs a whole number greater than zero`, standard output is empty, and the exit code is 2.
- Given any file, when the user runs `wordfreq --top -1 FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top abc FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top 2.5 FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top 3.0 FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top +3 FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top 1e2 FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top "" FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq FILE --top`, then the result is the same error, with exit code 2.
- Given no file `missing.txt`, when the user runs `wordfreq --top 0 missing.txt`, then standard error is `error: --top needs a whole number greater than zero` and the exit code is 2.
- Given no file `missing.txt`, when the user runs `wordfreq --top 2 missing.txt`, then standard error is `error: cannot read missing.txt` and the exit code is 2.

### JOB-report-word-frequencies.R8 · One --top option only

- Given a file with `b a b c a b`, when the user runs `wordfreq --top 1 --top 2 FILE`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.

## Interface

The user acts through a command. Thus, a check runs `python3 -m wordfreq` from the project root,
with the arguments of the acceptance line. The check reads standard output, standard error, and the
exit code. A check can also call `main` in the same process, as `tests/test_cli.py` does.

- Command `python3 -m wordfreq [--top N] FILE` in `wordfreq/__main__.py`
  - This file exists. It calls `main` and exits with the value that `main` returns.
  - In: zero or more arguments. The acceptance lines use these forms:
    - `FILE`: one file.
    - `--top N FILE`: the option before the file.
    - `FILE --top N`: the option after the file.
    - `--top N`: the option and no file.
    - `--top N1 --top N2 FILE`: the option two times.
    - `FILE --top`: the option as the last argument, with no value.
    - `FILE1 FILE2`: two files.
    - No arguments.
  - The argument right after `--top` is always its value, also when it starts with `-`, as in
    `--top -1 FILE`.
  - N is one argument. The acceptance lines use these values: `1`, `2`, `3`, `10`, `03`, `0`, `-1`,
    `abc`, `2.5`, `3.0`, `+3`, `1e2`, and the empty string `""`.
  - N is valid when it has only the digits 0 to 9 and its value is at least 1. For example, `03`
    is valid and means 3.
  - Out on success: the exit code is 0 and standard error is empty. Standard output has one line for
    each distinct word, as the word, a space, the count, and a newline.
  - The lines run from the highest count to the lowest. Words with the same count run in alphabetical
    order.
  - With `--top N`, standard output has only the first N lines. The cut comes after the sort, so
    the words with the same count at the cut stay in alphabetical order.
  - If N is more than the number of distinct words, all lines print. A file with no words gives no
    output.
  - errors: `TOP_INVALID`, the usage error, and the cannot-read error. The next three items give
    their texts.
    - `TOP_INVALID`: standard error is `error: --top needs a whole number greater than zero` and a
      newline. Standard output is empty. The exit code is 2. The code does not show, so a check
      expects the text and the exit code.
    - The usage error has no code in `DES-errors`. Standard error is `usage: wordfreq FILE` and a
      newline. Standard output is empty. The exit code is 2. It shows when the number of files is
      not one, or when `--top` comes two or more times.
    - The cannot-read error has no code in `DES-errors`, and exists already. Standard error is
      `error: cannot read <path>` and a newline. `<path>` is the FILE argument as the user wrote it.
      Standard output is empty. The exit code is 2.
  - The command reports only the first error of this list (assumed), because no acceptance line
    gives an order for two errors:
    1. `--top` comes two or more times: the usage error.
    2. The files are not exactly one, after the command removes each `--top` and its value: the
       usage error.
    3. N is missing or not valid: `TOP_INVALID`.
    4. The file cannot be read: the cannot-read error.
- `main(argv: list[str] | None = None, stdout: TextIO | None = None, stderr: TextIO | None = None) -> int`
  in `wordfreq/cli.py`
  - In: `argv` is the list of the arguments of the command, in the forms above. `stdout` and `stderr`
    are text streams. With `None`, `main` uses the real streams.
  - Out: the return value is the exit code, 0 or 2. The streams get the same text as the command gives.
  - errors: the same as the command: `TOP_INVALID`, the usage error, and the cannot-read error.
