# CH-0001 · Top option

Intent: IN-0001 · Scope: JOB-report-word-frequencies · Status: planned · Ticket: none · Branch: none · Base: main
Tests-Locked: none

## Delivers

The command `wordfreq` takes the option `--top N`. With this option, the command prints only the N most common words. A bad N gives the error `TOP_INVALID`. A second `--top` gives the usage line.

## Requirements

### JOB-report-word-frequencies.R5 · Usage line for a wrong number of arguments

- Given no arguments, when the user runs `wordfreq`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.
- Given the arguments `a.txt b.txt`, when the user runs `wordfreq a.txt b.txt`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.
- Given the arguments `--top 2` with no file, when the user runs `wordfreq --top 2`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.

### JOB-report-word-frequencies.R7 · Print only the N most common words

- Given a file with `b a b c a b`, when the user runs `wordfreq --top 2 FILE`, then the lines are `b 3` and `a 2`, and the exit code is 0.
- Given a file with `b a b c a b`, when the user runs `wordfreq FILE --top 2`, then the lines are `b 3` and `a 2`, and the exit code is 0.
- Given a file with `pear apple fig`, when the user runs `wordfreq --top 2 FILE`, then the lines are `apple 1` and `fig 1`.
- Given a file with `b a b c a b`, when the user runs `wordfreq --top 1 FILE`, then the output is `b 3`.
- Given a file with `b a b c a b`, when the user runs `wordfreq --top 10 FILE`, then the lines are `b 3`, `a 2`, `c 1`.
- Given a file with `b a b c a b`, when the user runs `wordfreq --top 03 FILE`, then the lines are `b 3`, `a 2`, `c 1`.
- Given an empty file, when the user runs `wordfreq --top 3 FILE`, then standard output is empty and the exit code is 0.
- Given any file, when the user runs `wordfreq --top 0 FILE`, then standard error is `error: --top needs a whole number greater than zero`, standard output is empty, and the exit code is 2.
- Given any file, when the user runs `wordfreq --top -1 FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top abc FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top 2.5 FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top 3.0 FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top +3 FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top 1e2 FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq --top "" FILE`, then the result is the same error, with exit code 2.
- Given any file, when the user runs `wordfreq FILE --top`, then the result is the same error, with exit code 2.
- Given no file `missing.txt`, when the user runs `wordfreq --top 0 missing.txt`, then standard error is `error: --top needs a whole number greater than zero` and the exit code is 2.
- Given no file `missing.txt`, when the user runs `wordfreq --top 2 missing.txt`, then standard error is `error: cannot read missing.txt` and the exit code is 2.

### JOB-report-word-frequencies.R8 · One --top option only

- Given a file with `b a b c a b`, when the user runs `wordfreq --top 1 --top 2 FILE`, then standard error is `usage: wordfreq FILE`, standard output is empty, and the exit code is 2.

## Interface

- Command `python3 -m wordfreq [--top N] FILE` in `wordfreq/__main__.py`
  - The acceptance lines write the command as `wordfreq`.
  - The command runs `main` with the process arguments. It exits with the code that `main` returns.
- `main(argv: list[str] | None = None, stdout: TextIO | None = None, stderr: TextIO | None = None) -> int` in `wordfreq/cli.py`
  - A check can call `main` in place of the command. The result is the same.
  - In: `argv` holds the arguments after the program name. A check passes `stdout` and `stderr` to read the output. A check writes its input file in a temporary folder.
  - In, the forms of `argv` that the acceptance lines use. `F` is the path of a readable file. `M` is the path of a file that does not exist.
    - `[]` and `[F1, F2]`: a wrong number of files (R5 usage line)
    - `["--top", "2"]`: the option and its value, with no file (R5 usage line)
    - `["--top", "2", F]` and `[F, "--top", "2"]`: the option before and after the file (R7 print N words)
    - `["--top", N, F]`, where N is `"1"`, `"10"`, `"03"`, `"0"`, `"-1"`, `"abc"`, `"2.5"`, `"3.0"`, `"+3"`, `"1e2"` or `""` (R7 print N words)
    - `[F, "--top"]`: the option last, with no value (R7 print N words)
    - `["--top", "0", M]` and `["--top", "2", M]`: a file that does not exist (R7 print N words)
    - `["--top", "1", "--top", "2", F]`: the option two times (R8 one option only)
  - How the command reads `argv`:
    - Only the exact argument `--top` is an option. Every other argument is a file name, also one that starts with `-` (assumed), as in the current code.
    - The argument right after `--top` is its value. The value can start with `-`, and it can be empty.
    - N is valid when it has at least one character, each character is one of `0` to `9`, and its number is at least 1. Thus `03` means 3. A digit of another script is not valid.
    - The command removes `--top` and its value. The arguments that stay are the files.
  - Out: the exit code, as an `int`. On success the exit code is `0`, standard error is empty, and standard output has the lines.
    - Each line is a word, a space, the count, and a newline. The lines run from the highest count to the lowest. Words with the same count run in alphabetical order.
    - Without `--top`, standard output has every line. With `--top N`, it has the first N lines. If N is more than the number of lines, it has every line.
    - A file with no words gives no lines.
  - errors:
    - `TOP_INVALID`: `--top` has no value, or N is not valid. This includes the case of `--top` as the only argument. Standard error is `error: --top needs a whole number greater than zero` and a newline. Standard output is empty. The exit code is `2`.
    - Usage error, which has no code in `DES-errors`: the number of files is not one, or the argument `--top` appears two or more times. Standard error is `usage: wordfreq FILE` and a newline. Standard output is empty. The exit code is `2`.
    - Read error, which has no code in `DES-errors`: the command cannot read the file. Standard error is `error: cannot read <path>` and a newline. `<path>` is the file argument as the user wrote it. Standard output is empty. The exit code is `2`.
  - The command makes its checks in this order (assumed), and stops at the first fault:
    1. The argument `--top` appears two or more times: the usage error.
    2. `--top` has no value, or N is not valid: `TOP_INVALID`.
    3. The number of files is not one: the usage error.
    4. The command cannot read the file: the read error.
  - This order matches a usual command line parser. A parser reports a bad option value before it reports a missing file.
