## Intent

Today one timeout from the payments API makes `HttpClient.get` raise an error. The error fails the whole nightly sync, and a person must run the sync again by hand.

After this change, `HttpClient.get` tries a failed call again. A call gets 4 attempts in total, with a longer wait before each new attempt. A short blip from the payments API then does not fail the nightly sync. The refund path does not change.

**Not doing:** Retry a POST call. The refund POST must never retry, because a retry could pay a customer twice.

**Words used here:**

- **Blip:** a short failure of the payments API that ends by itself.
- **Attempt:** one call to the API. The first call is attempt 1.
- **Backoff:** a wait that becomes longer before each new attempt.
- **Jitter:** a small random time that is added to a wait.
