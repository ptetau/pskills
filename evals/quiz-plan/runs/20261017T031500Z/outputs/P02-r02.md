## Intent

Today `orders.status` is free text. Typos such as 'shiped' and 'canceled' get in. The dashboard counts each spelling as its own status, so the per-status counts are wrong.

After this change, `orders.status` is a Postgres enum named `order_status`. The enum has five values: pending, paid, shipped, cancelled, and refunded. The database rejects any other value. The migration folds the two known typos. To fold a typo is to change the typo value to its fixed value. The migration changes 'shiped' to 'shipped' and 'canceled' to 'cancelled'.

A person can observe three results:

- The dashboard count for each status equals the count from `SELECT status, count(*) FROM orders GROUP BY status` before the migration, with the typo rows added to their fixed values.
- The dashboard has a label for each of the five statuses. Today `LABELS` has no label for `refunded`.
- The public REST API keeps its JSON shape. For a folded row, the API returns the fixed spelling.
