Remit: security

Problems: none

Follow-ups:
- `Store::save` writes the data file with one `fs::write` call. Two requests at the same time can lose an update, or leave a half-written file. An atomic write (write a temp file, then rename) would prevent this. The spec does not ask for it, so it is new behaviour.

Notes:
- The file path is set once in `Store::new`. No request input builds a path, a command, or a query.
- The text of an item has its tabs and line breaks replaced, so the text cannot add a line or a `*` mark to the file.
- The id is parsed as a number, and a line that does not parse is skipped.
- No secret is in the code.
