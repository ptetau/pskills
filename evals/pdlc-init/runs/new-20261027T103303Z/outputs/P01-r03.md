This folder holds the pdlc state for this project. This file holds the definitions and the

## Core rules

1. pdlc runs only on a Sonnet 5.5 class model or above. On a lower model, for example a

6. The test writer writes the checks from the spec, before the code. The acceptance checks

7. Each review remit gets one fresh reviewer, and the reviewer sees only its packet.
8. A change merges only when all of these are true, as `bin/check_merge.py` confirms:

## Code maps

The "Code map" of each job and capability lists what it owns, and gives the scope of a
change.

- A job owns its entry points (a route or request handler, a command, a page script or
  event handler), with its line in any routing table or command list.
- A capability owns the shared logic under them: storage, outside services, and the
  plumbing every job uses (starting the server, routing, reading a request, writing a
  reply).
- A file with parts of several specs is shared. Each code map names its parts:
  `src/server.py: POST /reset route and handle_reset` for a job, and
  `src/server.py: the rest` for the capability that holds the plumbing.
- A change can list a shared file in "Files" with its own parts, and edits only those
  parts. A new route or command adds its own part beside the others.
- The README of the project is in no code map. A change changes only what the README says
  about its own spec, and how to run the app and the checks.

## Who does what

| Who | Does | Never |

| `pdlc:test-writer` | writes checks from the spec | reads app code |
| `pdlc:builder` | writes app code until the checks pass | changes checks or `pdlc/` files |
| `pdlc:reviewer` | judges one packet for one remit | sees anything other than its packet |
| `pdlc:recon` | maps existing code | writes anything |

## Stages and handoffs

The intent stages are intake → ready → change → acceptance. The change stages are tests →
build → show → `verify`. `/pdlc:ship` runs them all.

- Each stage starts from the latest handoff, and ends with a new one from
  `templates/handoff.md`, which replaces the old one. Git keeps the history.
- An intent stage writes the "Handoff" of the intent, with the template sections as `###`
  headings. A change stage writes `changes/CH-xxxx-name/handoff.md`.
- The title comes from the list in the template. Every section stays, with "none" under an
  empty one. The time comes from the real clock (`date -Iseconds`).
- A handoff says only what the files show, with real counts of the checks that ran and of
  the acceptance lines shown.

At the end of each stage, and at each stop:

- The statuses that the stage owns are set. The tests stage sets `testing`, then
  `building`. The `verify` stage sets `in review` when everything passed.
  `bin/record_merges.py` sets `merged` and `done`.
- Everything that the stage wrote is committed: specs, the intent, the change folder,
  packets, and results. `git status --porcelain` shows nothing.
- The files that the checks leave behind (caches, build output) are deleted, not
  committed. Init lists their folders in `.gitignore`.
- The tracker port knows each status that changed ("Ports").

## Checks before code

The acceptance stage and the tests stage share these rules. The lock line is
`Acceptance-Locked:` in the intent, or `Tests-Locked:` right under the header of the
change spec.

- Red: before the lock, each check of new behaviour fails. A check that passes goes back
  to the test writer with the reason.
- A check of existing behaviour (only the words changed) can pass. After a send-back from
  build or `verify`, app code exists, so a corrected check can pass. The skill records
  each such result in the progress log, or in the intent "Notes" for acceptance.
- A check that fails because a command, a route, or a function does not exist yet counts
  as failing. The error comes from the missing interface, not from a mistake in the check.
- A run has a time limit of a few minutes. A run that does not finish has a broken check,
  not a red one. The broken check goes back to the test writer before the lock.
- When the test writer reports a missing "Interface" item, the skill adds the item to the
  change spec itself (it can see the code). Then the test writer runs again.
- Lock: the commit of the checks. Its hash goes on the lock line, and replaces an older
  hash.
- After the lock, only the test writer changes the checks, and only through the skill of
  the stage. Each change makes a new lock, and each lock gets its own review. The merge
  check refuses a tests review of an older lock.
- Review: `bin/make_packets.py` makes the tests packet, and a fresh `pdlc:reviewer` gets
  only its path. A later packet is a re-review: the earlier problems, and the diff of the
  checks since the earlier lock. The reviewer judges only these two items.
- A failed review sends its problems to the test writer, and red, lock, and review run
  again ("Rounds").

## Acceptance checks

Each intent has one acceptance file, at the "acceptance file" path in `config.md`. Its
checks prove the acceptance lines through what a user uses. They can use each feature of
the intent, and each feature that exists already.

- The acceptance stage writes, locks, and reviews the file before the first change.
  `Acceptance-File:` and `Acceptance-Locked:` in the intent record the file and the lock.
- A component check (a check of a change) uses only the interface of its change and of
  earlier changes.
- The "all" command does not run an acceptance file. Thus, the acceptance checks of an
  open intent can fail until its last change, and main stays green.
- The build and `verify` stages run all checks and **run earlier acceptance**, and for the
  last change also **run acceptance**. Each check must pass. The `verify` stage writes the
  commit of that run on `Acceptance-Passed:`.
- For an earlier change, a failure of **run acceptance** is expected, and is not reported.
- After the intent merges, its acceptance checks stay, and each later change keeps them
  green.

## Rounds

A round is one failed tests or acceptance review, one failed `verify`, or one builder
report that a check is wrong. A fix of a check before its lock is not a round. An agent
blocked twice is one round. Each change has two rounds, and so does the acceptance stage
of each intent. The third failure of the same stage stops the work, and the skill asks the
user.

## Where pdlc commits

- Init commits on main. So do intake, ready, and change while no pdlc branch is unmerged.
  The records of pdlc are not code, so this is by design, also where the usual rule is to
  branch first.
- The acceptance stage commits on the intent branch, `pdlc/IN-xxxx-<short-name>`, and
  starts it if necessary. Thus, the acceptance checks go to main only with their code.
- A change commits its code, status, lock, and handoff on its own branch. On main, an
  unmerged change still has the status `planned`.
- While any pdlc branch is unmerged, only `bin/record_merges.py` commits on main, and the
  intent stages work on the intent branch. That branch starts from the newest unmerged
  branch: the first line of
  `git branch --no-merged main --list 'pdlc/*' --sort=-committerdate`, with the pattern of
  `DES-pdlc-branches` (the branch names). The `Branch:` of the intent names it.
- Thus, the spec patches come after the work that they change, and every branch merges
  into main in order, with no conflicts.
- Nothing is committed on a branch that merged into main, not even a status or a `Base:`.
  Work found after a change merged is a new change. The merge check refuses the branch of
  a merged change if it has new commits.
- All work stays in the project checkout, not in a git worktree. The agents, the guard,
  and the scripts use the paths of the checkout.
- A skill commits its work before `git switch <branch>`. When `git switch` refuses, the
  skill commits or deletes what `git status` shows, for example `__pycache__/`.
- A skill selects an intent or a change by its status only where it lives. It lists the
  unmerged branches, and reads each `change.md` from its own branch
  (`git show <branch>:pdlc/changes/<folder>/change.md`). It reads each intent from the
  newest branch that has it. A change with no branch is `planned`.

## Stacked changes

A change is built on the branch of the change before it, also before that change merges.
Its `Base:` names that branch, and its pull request targets that branch.

- The base is the branch of the previous change in the intent "Changes". For the first
  change, it is the newest unmerged change of an earlier intent, or else main.
- If the intent has a `Branch:`, the first change starts from that branch, and so carries
  the spec patches and the acceptance checks. When that branch lacks the base
  (`git merge-base --is-ancestor <base> <intent branch>` fails), the tests stage merges the
  base into it first, with the trailer `Intent`.
- In that merge, a requirement that the intent changed keeps the text and status of the
  intent. Each other requirement keeps the text and status of the base.
- The changes of an intent merge together, bottom first. The merge check fails each of
  them until all are `in review`.
- The base can merge into main before `verify` proposes the change
  (`git merge-base --is-ancestor <base> main` succeeds). Then `Base:` becomes main on the
  branch of the change, and the proposal targets main. A merged branch keeps its `Base:`.

## Statuses

- Intent: new → specifying → ready → building → in review → done. Also paused, cancelled.
- Requirement: proposed → ready → built → verified. Also retiring.
- Change: planned → testing → building → in review → merged. Also cancelled.
- Spec file: stub (no requirements written yet) or active.

## Questions

- A question is short, and comes one at a time, with two or three answers. The recommended
  answer has a mark and one line on why. The reply `skip` takes it.
- A decision that a skill makes without an instruction (a name, a limit, a message, an
  order, a default answer) has the mark `(assumed)` where the spec or change spec states
  it. The handoff lists it too. Thus, no guess stays hidden.
- The mark is plain, right after the words that it marks, with any reason outside the
  brackets: "at most 20 items (assumed), to keep the list short". In a change, the merge
  check rejects `(limit assumed)`, `*(assumed)*`, and each mark that does not start with
  `(assumed`.
- With `defaults`, a skill asks nothing, and takes its recommended answer. Each answer goes
  as `<question> → <answer> (assumed)` in "Decided on defaults" in the handoff and in the
  intent "Notes", so that the user can change it.

## Spec patches

These rules hold each time that a skill writes or changes a spec.

- Where a behaviour belongs:
  - What a user does through a route, a command, or a page, and gets back: a **job**,
    also in a shared file.
  - What the system offers to jobs (a store, an outside service, shared plumbing): a
    **capability**. Its requirements give what it offers to jobs, not the behaviour of one
    job.
  - How the project does something everywhere: a **design** spec.
  - How the output of one job looks (a format, a wording, a layout): that **job**, also
    when a capability makes the value. The job has a line for each place that shows it.
  - A behaviour that many jobs share (a reply format, an error shape, an unreadable store,
    a size limit on each request): one time, in the capability or design spec that those
    jobs use. For example, "every email has an unsubscribe link" goes in `CAP-email`.
  - An existing spec comes first. A new capability has its boundary around a thing that is
    likely to change (a vendor, a set of rules, a store), and is named for it:
    `CAP-payments`, not `CAP-checkout-button`.
- The words of the intent bind. Each example in the intent (an output, a message, a value)
  is an acceptance line, exactly. The plain reading holds for every value, also zero,
  empty, and an integer. No `(assumed)` reading or recommendation narrows the words to
  keep the old behaviour, or changes the result of an example.
- The newest words win. When the intent asks for something that an older requirement or
  an `(assumed)` detail rules out, the older text changes to match. This case is a changed
  requirement, not a contradiction. The intent "Notes" get
  `<ID>: was "<old>", now "<new>"`.
- No old wording. For each changed or retired requirement, a search of `pdlc/specs/` and
  the README finds the old words (a command, a message, a value, a button). No title,
  summary, example, acceptance line, note, "Known gap" line, or "Changes" list in the
  specs shows them. Each cross-reference (`see CAP-x.R4`) points at the rule it means.
- The README is app code, so a spec stage does not edit it. Each README line with old
  behaviour gets `README: "<old line>" → <requirement>` in the intent "Notes". The change
  for that requirement fixes the line.
- A spec stage does not edit a change spec (`changes/*/change.md`). An unmerged change
  keeps what it copied.

## New behaviour needs approval

New behaviour is behaviour that no acceptance line, design spec, or remit rule asks for.
Nobody builds it on the branch of a change. The `verify` stage files it as a `new` intent
whose "Notes" start with `Awaits approval:`. No skill takes up such an intent on its own,
also with `defaults`. Work starts only when the user names it, and then the line goes.

## Bookkeeping on main

Before any work, each skill that names this section switches to main, pulls main if there
is a remote, and runs `python3 pdlc/bin/record_merges.py`. The script sets each change
whose branch merged to `merged`, and each intent whose changes all merged to `done`. Then
it commits those records on main. Nobody does this bookkeeping by hand, or on another
branch.

## pdlc's own files

`README.md`, `ports/`, `adapters/`, `templates/`, and `bin/` come from the pdlc plugin.
They change only in a pdlc upgrade, on main, in a commit of their own, and not on the
branch of a change. An upgrade can also refresh the `DES-pdlc-*` design specs and the
`reviews/` files that say `Default: yes`. A file that the project changes says
`Default: no`, and belongs to the project.

- No skill calls a tool directly when a port covers that tool.
- After each status change of an intent or a change, the tracker port gets it. With the

### pdlc/bin/check_merge.py
```
#!/usr/bin/env python3
"""pdlc merge check.

A change may merge only when:
  - every requirement it lists is verified (and every retired one is gone from its spec);
  - each assumption marker in its change spec and requirements starts with "(assumed",
    with no emphasis around it: "(assumed)", "(assumed limit)", "(assumed: a reason)";
  - its checks are locked, and no check file changed after the lock;
  - the tests review judged the checks as they are locked now: its packet carries the
    current lock;
  - the tests review names a wrong version of the code that each check fails on. A
    re-review (its packet says "Earlier review:") names one only for each check that
    changed since the earlier lock. If no check changed, it needs none;
  - every review remit named in pdlc/config.md passed;
  - the branch merges into main without conflicts;
  - its intent is in pdlc/inbox, and every other change of the intent is "in review" or
    "merged" on its own branch, so the intent's changes merge together;
  - the acceptance checks of its intent are locked ("Acceptance-Locked:" in the intent), the
    tests review judged them at that lock with "Wrong versions", and the acceptance file did
    not change after the lock;
  - the acceptance checks passed at the top of the stack: the intent on the branch of its
    last change says "Acceptance-Passed: <hash>", that commit comes after the lock, and only
    pdlc/ files changed after it. A change that only retires requirements is permitted
    to have "Acceptance-Locked: none";
  - it hasn't merged already: a merged change's branch takes no new commits.

Usage:
  python3 pdlc/bin/check_merge.py CH-0031   check one change
  python3 pdlc/bin/check_merge.py           check the change for the current branch, or,
                                            if no change uses this branch, every change
                                            with status "in review"

In CI, the script reads the current branch from GITHUB_HEAD_REF when that variable is set.
Run it from the project root. Exit code 0 means the change may merge.
"""
import os
import re
import subprocess
import sys
from pathlib import Path

REQ = re.compile(r"^### ((?:JOB|CAP|DES)-[a-z0-9-]+\.R\d+)\b(.*)$", re.M)
KINDS = {"JOB": "jobs", "CAP": "capabilities", "DES": "design"}
DEFAULT_REMITS = ["tests", "specification", "security", "quality", "compliance", "privacy"]
READY = ("in review", "merged")
HASH = re.compile(r"^[0-9a-f]{7,40}$")
# A marker with emphasis (*(assumed)*), or brackets that hold the word "assumed". A marker
# passes when it starts with "(assumed".
MARKER = re.compile(r"[*_]+\(assumed\b[^()\n]*\)[*_]+|\([^()\n]*\bassumed\b[^()\n]*\)", re.I)


def section(text, title):
    """The text under a '## title' heading, up to the next '## ' heading."""
    match = re.search(r"^## %s\s*$(.*?)(?=^## |\Z)" % re.escape(title), text, re.M | re.S)
    return match.group(1) if match else ""


def requirement_text(root, req_id):
    """The requirement's heading and text in its spec, or None if it isn't there."""
    spec_id = req_id.rsplit(".", 1)[0]
    spec = root / "pdlc" / "specs" / KINDS[spec_id.split("-", 1)[0]] / (spec_id + ".md")
    if not spec.exists():
        return None
    text = spec.read_text()
    heading = re.search(r"^### %s\b.*$" % re.escape(req_id), text, re.M)
    if not heading:
        return None
    body = text[heading.end():]
    end = re.search(r"^##", body, re.M)
    return heading.group(0) + (body[:end.start()] if end else body)


def status_of(root, req_id):
    """The requirement's status in its spec, 'missing' if it has none, None if not there."""
    body = requirement_text(root, req_id)
    if body is None:
        return None
    status = re.search(r"^Status:\s*([a-z ]+?)\s*(?:·|$)", body, re.M)
    return status.group(1) if status else "missing"


def marker_problems(where, text):
    """Each assumption marker in the text that does not start with "(assumed"."""
    return ['%s: write "%s" so it starts with "(assumed", for example "(assumed)"'
            % (where, found.group(0)) for found in MARKER.finditer(text or "")
            if not found.group(0).startswith("(assumed")]


def remits(root):
    """The review remits pdlc/config.md asks for."""
    config = root / "pdlc" / "config.md"
    text = config.read_text() if config.exists() else ""
    line = re.search(r"^- remits:\s*(.+)$", section(text, "Reviews"), re.M)
    if not line:
        return DEFAULT_REMITS
    return [r.strip() for r in line.group(1).split(",") if r.strip() and r.strip() != "none"]


def check_files(text):
    """The paths listed under '## Check files'."""
    paths = re.findall(r"^-\s+`?([^`\s]+)`?", section(text, "Check files"), re.M)
    return [p for p in paths if p.lower() != "none"]


def has_lock(packet, lock, name="Tests-Locked"):
    """True when the text of a tests packet carries this lock, copied from the change spec
    (Tests-Locked) or from the intent (Acceptance-Locked)."""
    seen = re.findall(r"^%s:\s*([0-9a-f]{7,40})\b" % name, packet or "", re.M)
    return bool(seen) and (seen[-1].startswith(lock) or lock.startswith(seen[-1]))


def reviewed_lock(folder, lock):
    """True when the tests packet carries this lock, copied from the change spec."""
    packet = folder / "review" / "tests" / "packet.md"
    return packet.exists() and has_lock(packet.read_text(), lock)


def wrong_version_lines(text):
    """The lines under "Wrong versions" in the text of a tests review's result."""
    block = re.search(r"^#*\s*Wrong versions:?\s*$(.*?)(?=^[^\s-]|\Z)", text or "", re.M | re.S)
    lines = re.findall(r"^\s*-\s+(.+?)\s*$", block.group(1), re.M) if block else []
    return [line for line in lines if line.lower() != "none"]


def wrong_versions(folder):
    """The lines under "Wrong versions" in the tests review's result."""
    result = folder / "review" / "tests" / "result.md"
    return wrong_version_lines(result.read_text() if result.exists() else "")


def git(root, *args):
    return subprocess.run(["git", *args], cwd=root, capture_output=True, text=True)


def checks_unchanged_since_earlier_review(root, folder, lock, checks):
    """True when the tests packet is a re-review, and no check file changed between the
    lock that the earlier review judged and this lock."""
    packet = folder / "review" / "tests" / "packet.md"
    return unchanged_since_earlier_review(root, packet.read_text() if packet.exists() else "",
                                          lock, checks)


def unchanged_since_earlier_review(root, text, lock, checks):
    """True when the text of a tests packet is a re-review, and no check file changed
    between the lock that the earlier review judged and this lock."""
    earlier = re.search(r"^Earlier review:\s*([0-9a-f]{7,40})\b", text or "", re.M)
    if not earlier or not lock:
        return False
    diff = git(root, "diff", "--name-only", earlier.group(1), lock, "--", *checks)
    return diff.returncode == 0 and not diff.stdout.strip()


def field(text, name):
    """A header field of a change spec or intent, such as Status or Branch. The value is
    bare: "IN-0001 (poll-input-errors)" gives "IN-0001", and "`pdlc/CH-0001-x`" gives
    "pdlc/CH-0001-x"."""
    match = re.search(r"\b%s:[ \t]*([^·\n]*?)[ \t]*(?:·|$)" % name, text, re.M)
    if not match:
        return None
    value = match.group(1).replace("`", "")
    return re.sub(r"\s+\(.*\)$", "", value).strip()


def show(root, ref, path):
    """A file as it is on a branch, or None if git can't find it there."""
    out = git(root, "show", "%s:%s" % (ref, path))
    return out.stdout if out.returncode == 0 else None


def branches(root):
    """Every local and remote branch git knows."""
    out = git(root, "for-each-ref", "--format=%(refname:short)", "refs/heads", "refs/remotes")
    return out.stdout.split() if out.returncode == 0 else []


def change_id(folder):
    """CH-0031 for the folder CH-0031-email-templates."""
    return "-".join(folder.name.split("-", 2)[:2])


def own_branch(root, path, refs):
    """The branch, as git knows it, that a change spec names as its own. None when the
    change has no branch."""
    for ref in refs:
        text = show(root, ref, path)
        branch = field(text, "Branch") if text else None
        if branch and branch != "none" and (ref == branch or ref.endswith("/" + branch)):
            return ref
    return None


def status_on_own_branch(root, path, refs):
    """A change's status on its own branch, the one its change spec names. A change whose
    branch is gone counts as merged if main's copy reads "in review" or "merged". None
    when it has no branch."""
    ref = own_branch(root, path, refs)
    if ref:
        return field(show(root, ref, path), "Status")
    on_main = show(root, "main", path) or show(root, "origin/main", path)
    status = field(on_main, "Status") if on_main else None
    return status if status in READY else None


def partners_not_ready(root, folder, text):
    """Problems with the other changes of this change's intent: each must be ready too."""
    intent = field(text, "Intent")
    if not intent or intent == "none":
        return []
    found = sorted((root / "pdlc" / "inbox").glob("%s-*.md" % intent))
    if not found:
        return ["%s is not in pdlc/inbox, so the check cannot find the other changes of the "
                "intent" % intent]
    listed = re.findall(r"\bCH-\d+\b", section(found[0].read_text(), "Changes"))
    problems, refs = [], branches(root)
    for other in dict.fromkeys(listed):
        if other == change_id(folder):
            continue
        specs = sorted((root / "pdlc" / "changes").glob(other + "-*/change.md"))
        path = "pdlc/changes/%s/change.md" % specs[0].parent.name if specs else None
        status = status_on_own_branch(root, path, refs) if path else None
        if status is None:
            problems.append("%s of %s is not ready (no branch)" % (other, intent))
        elif status not in READY:
            problems.append("%s of %s is not ready (status: %s)" % (other, intent, status))
    return problems


def record(text, name):
    """The value of a line such as "Acceptance-Locked: 1a2b3c4" in the "Acceptance checks"
    section of an intent: the last such line, without backticks. None if there is none."""
    found = re.findall(r"^%s:[ \t]*`?([^`\s]+)`?" % re.escape(name),
                       section(text or "", "Acceptance checks"), re.M)
    return found[-1] if found else None


def changed_files(root, old, new, *paths):
    """The files that differ between two commits, or None if git can't compare them."""
    out = git(root, "diff", "--name-only", old, new, "--", *paths)
    return out.stdout.split() if out.returncode == 0 else None


def is_ancestor(root, old, new):
    return git(root, "merge-base", "--is-ancestor", old, new).returncode == 0


def acceptance_problems(root, folder, text, reqs):
    """Problems with the acceptance checks of this change's intent. The checks must be
    locked, reviewed at the lock, unchanged since the lock, and recorded as passing at the
    top of the stack: the branch of the last change of the intent."""
    intent = field(text, "Intent")
    found = sorted((root / "pdlc" / "inbox").glob("%s-*.md" % intent)) if intent else []
    if not found:
        return []  # partners_not_ready names the missing intent
    listed = list(dict.fromkeys(re.findall(r"\bCH-\d+\b", section(found[0].read_text(), "Changes"))))
    top_id = listed[-1] if listed else change_id(folder)
    # The top of the stack is the branch of the last change. In CI, HEAD can be a merge of
    # the pull request into main, so HEAD stands in only when git knows no such branch.
    specs = sorted((root / "pdlc" / "changes").glob(top_id + "-*/change.md"))
    top = own_branch(root, specs[0].relative_to(root).as_posix(), branches(root)) if specs else None
    if not top and top_id == change_id(folder):
        top = "HEAD"

    def read(path):
        """A file at the top of the stack. This checkout stands in when the top is HEAD, or
        when the top change has no branch yet."""
        if top and top != "HEAD":
            return show(root, top, path)
        return (root / path).read_text() if (root / path).exists() else None

    intent_text = read(found[0].relative_to(root).as_posix()) or found[0].read_text()
    checks, lock = record(intent_text, "Acceptance-File"), record(intent_text, "Acceptance-Locked")
    passed = record(intent_text, "Acceptance-Passed")
    if not lock or not HASH.match(lock):
        if lock == "none" and reqs and all("(retire)" in rest for _, rest in reqs):
            return []
        return ["acceptance checks of %s are not locked (no Acceptance-Locked hash in the "
                "intent); run /pdlc:acceptance" % intent]
    if not checks or checks == "none":
        return ["%s names no Acceptance-File, so the check cannot find its acceptance checks"
                % intent]
    problems = []

    if "tests" in remits(root):
        review = "pdlc/acceptance/%s/review/tests/" % found[0].stem
        packet, result = read(review + "packet.md"), read(review + "result.md")
        if not has_lock(packet, lock, "Acceptance-Locked"):
            problems.append("acceptance review of %s is not of the current lock %s; review the "
                            "acceptance checks again" % (intent, lock))
        if result is None:
            problems.append("acceptance review of %s has no result. Run python3 "
                            "pdlc/bin/make_packets.py %s, and start a reviewer" % (intent, intent))
        elif not re.match(r"\s*Result:\s*pass\b", result, re.I):
            problems.append("acceptance review of %s did not pass" % intent)
        else:
            lines = wrong_version_lines(result)
            if not lines and not unchanged_since_earlier_review(root, packet, lock, [checks]):
                problems.append('acceptance review of %s lists no "Wrong versions"; review the '
                                'acceptance checks again' % intent)
            for line in lines:
                if re.search(r"·\s*passes\b", line, re.I):
                    problems.append("acceptance review of %s: a check passes a wrong version: %s"
                                    % (intent, line))

    # A change below a later lock holds an older copy of the file. That copy must not change
    # after the change got it, so the diff starts where this branch and the lock meet.
    since = git(root, "merge-base", "HEAD", lock).stdout.strip()
    changed = changed_files(root, since, "HEAD", checks) if since else None
    if changed is None:
        problems.append("can't compare the acceptance checks of %s with the lock %s" % (intent, lock))
    locked_changed = list(changed or [])

    if not top:
        return problems  # partners_not_ready says that the top change has no branch
    if not passed or not HASH.match(passed):
        problems.append("acceptance checks of %s are not ready: no Acceptance-Passed at the top "
                        "of the stack (%s)" % (intent, top_id))
    elif not is_ancestor(root, lock, passed):
        problems.append("Acceptance-Passed %s of %s does not come after its lock %s; run the acceptance "
                        "checks again" % (passed, intent, lock))
    elif not is_ancestor(root, passed, top):
        problems.append("Acceptance-Passed %s of %s is not on the branch of %s; run the acceptance "
                        "checks there" % (passed, intent, top_id))
    else:
        locked_changed += changed_files(root, lock, passed, checks) or []
        later = [f for f in changed_files(root, passed, top) or [] if not f.startswith("pdlc/")]
        if later:
            problems.append("files changed after the acceptance checks of %s passed: %s; run them "
                            "again" % (intent, ", ".join(later)))
    problems += ["changed after the acceptance checks were locked: %s" % path
                 for path in dict.fromkeys(locked_changed)]
    return problems


def merged_already(root, folder):
    """True when main says this change merged, yet this branch has commits main doesn't."""
    on_main = show(root, "main", "pdlc/changes/%s/change.md" % folder.name)
    if not on_main or field(on_main, "Status") != "merged":
        return False
    ahead = git(root, "rev-list", "--count", "main..HEAD")
    return ahead.returncode == 0 and int(ahead.stdout.strip() or 0) > 0


def conflicts_with_main(root):
    """Files that conflict when this branch merges into main. Empty when it merges
    cleanly, when there is no main, when this is main, or when git can't tell."""
    try:
        head = git(root, "rev-parse", "--verify", "-q", "HEAD")
        main = git(root, "rev-parse", "--verify", "-q", "main")
        if head.returncode or main.returncode or head.stdout == main.stdout:
            return []
        out = git(root, "merge-tree", "--write-tree", "--name-only", "--no-messages",
                  "main", "HEAD")
    except OSError:
        return []
    if out.returncode != 1:
        return []
    return sorted(set(out.stdout.split()[1:]))


def check_change(root, folder):
    """A list of problems with one change. Empty means it may merge."""
    problems = []
    text = (folder / "change.md").read_text()

    reqs = REQ.findall(section(text, "Requirements"))
    if not reqs:
        problems.append("lists no requirements")
    for req_id, rest in reqs:
        status = status_of(root, req_id)
        if "(retire)" in rest:
            if status is not None:
                problems.append("%s is marked (retire) but is still in its spec" % req_id)
        elif status is None:
            problems.append("%s is not in its spec" % req_id)
        elif status != "verified":
            problems.append("%s is %s, not verified" % (req_id, status))

    problems += marker_problems("change.md", text)
    for req_id, _ in reqs:
        problems += marker_problems(req_id, requirement_text(root, req_id))

    checks = check_files(text)
    # A re-lock may leave the older line in place. The newest (last) line counts.
    locks = list(re.finditer(r"^Tests-Locked:\s*([0-9a-f]{7,40})\b", text, re.M))
    lock = locks[-1] if locks else None
    if checks and not lock:
        problems.append("tests are not locked (no Tests-Locked line)")
    elif checks:
        diff = git(root, "diff", "--name-only", lock.group(1), "HEAD", "--", *checks)
        if diff.returncode != 0:
            problems.append("can't compare tests with the lock %s" % lock.group(1))
        for path in diff.stdout.split():
            problems.append("changed after the tests were locked: %s" % path)

    wanted = remits(root)
    if lock and "tests" in wanted and not reviewed_lock(folder, lock.group(1)):
        problems.append("tests review is not of the current lock %s; review the checks again"
                        % lock.group(1))

    for remit in wanted:
        result = folder / "review" / remit / "result.md"
        if not result.exists():
            problems.append("%s review has no result. Run python3 pdlc/bin/make_packets.py %s %s, "
                            "and start a reviewer if it writes a packet"
                            % (remit, change_id(folder), remit))
        elif not re.match(r"\s*Result:\s*pass\b", result.read_text(), re.I):
            problems.append("%s review did not pass" % remit)

    if checks and "tests" in wanted and (folder / "review" / "tests" / "result.md").exists():
        lines = wrong_versions(folder)
        if not lines and not checks_unchanged_since_earlier_review(
                root, folder, lock.group(1) if lock else None, checks):
            problems.append('tests review lists no "Wrong versions"; review the checks again')
        for line in lines:
            if re.search(r"·\s*passes\b", line, re.I):
                problems.append("tests review: a check passes a wrong version: %s" % line)

    for path in conflicts_with_main(root):
        problems.append("conflicts with main: %s" % path)

    problems += partners_not_ready(root, folder, text)
    problems += acceptance_problems(root, folder, text, reqs)

    if merged_already(root, folder):
        problems.append("%s already merged; new commits on its branch won't reach main. "
                        "Start a new change." % change_id(folder))
    return problems


def current_branch(root):
    """The branch being merged: GITHUB_HEAD_REF in CI, else git's current branch."""
    if os.environ.get("GITHUB_HEAD_REF"):
        return os.environ["GITHUB_HEAD_REF"]
    try:
        out = git(root, "rev-parse", "--abbrev-ref", "HEAD")
    except OSError:
        return None
    return out.stdout.strip() if out.returncode == 0 else None


def main(argv, root=Path("."), branch=None):
    changes = root / "pdlc" / "changes"
    everything = sorted(p.parent for p in changes.glob("CH-*/change.md"))
    if len(argv) > 1:
        folders = [f for f in everything if f.name.startswith(argv[1] + "-")]
        if not folders:
            print("No change spec found for %s" % argv[1])
            return 1
    else:
        branch = branch or current_branch(root)
        folders = [f for f in everything
                   if branch and field((f / "change.md").read_text(), "Branch") == branch]
        if not folders:
            folders = [f for f in everything
                       if field((f / "change.md").read_text(), "Status") == "in review"]
    failed = False
    for folder in folders:
        problems = check_change(root, folder)
        name = change_id(folder)
        if problems:
            failed = True
            print("FAIL %s" % name)
            for problem in problems:
                print("  - %s" % problem)
        else:
            print("ok   %s" % name)
    return 1 if failed else 0


if __name__ == "__main__":
    sys.exit(main(sys.argv))

#!/usr/bin/env python3
"""pdlc writing check. Finds breaks of the writing rules that a script can find well.

Usage:
  python3 pdlc/bin/check_writing.py [paths...]
  python3 pdlc/bin/check_writing.py --since <branch> [paths...]

A path is a file or a folder. For a folder, it checks every .md file in the folder. With
no paths, it checks the .md files changed on this branch (git diff --name-only
main...HEAD). If there is no main, it checks every .md file under the current folder.
With --since, it reports only the lines committed since that branch.

It checks four rules of DES-writing-style (the writing rules):
  - sentence length: a sentence of more than 25 words, or an instruction of
    more than 20. An instruction starts with a command verb, such as "Run" or "Use".
  - NZ spelling: common US forms, such as "organize", "color", "center" and
    "gray". It gives the NZ form to write.
  - ID alone: a pdlc ID (IN-0001, CAP-email, CAP-email.R3) or a bare
    requirement number (R3) with no name next to it. A name is next to it when the
    sentence goes on with "(", " · ", ":", a dash and words, or a quoted name. A name
    is also next to it when the ID is in brackets after the name.
  - conversation: phrases that tell how the text came about, such as "as you
    asked", "I've" or "last round". "Here is" counts only at the start of a sentence.

It doesn't read fenced code blocks, inline code, URLs, HTML comments, or front matter
other than "description". Quoted text counts toward a sentence's length, but no other
rule reads it. These may hold an ID alone: a heading, a table row, a field line ("Req:",
"Intent:", "Status:"), a list of IDs and a placeholder (IN-xxxx). A line that ends with
<!-- writing: ok --> is a deliberate exception: the check reports nothing on it.

Reviewers judge what a script can't judge well: clear references to nouns, concrete
examples, being concise, the active voice, and the other sentence rules.

Output: one line per finding, "<file>:<line> · <rule> · <what is wrong> · <suggestion>",
then the count. Exit code 1 means it found something.
"""
import re
import subprocess
import sys
from pathlib import Path

MARKER = "<!-- writing: ok -->"
SENTENCE_LIMIT = 25
INSTRUCTION_LIMIT = 20
COMMANDS = {"run", "use", "write", "read", "set", "add", "check", "give", "keep", "make",
            "put", "start", "stop", "tell", "take", "list", "commit", "ask", "copy",
            "create", "delete", "don't", "fix", "follow", "never", "pick", "remove",
            "replace", "skip", "switch", "wait"}
RULES = ["sentence length", "NZ spelling", "ID alone", "conversation"]

# US forms and the NZ form to write. The check matches each as a whole word, in any case.
SPELLING = {
    "center": "centre", "centers": "centres", "centered": "centred", "centering": "centring",
    "theater": "theatre", "theaters": "theatres", "fiber": "fibre", "fibers": "fibres",
    "liter": "litre", "liters": "litres", "kilometer": "kilometre", "kilometers": "kilometres",
    "centimeter": "centimetre", "centimeters": "centimetres",
    "millimeter": "millimetre", "millimeters": "millimetres",
    "catalog": "catalogue", "catalogs": "catalogues", "cataloged": "catalogued",
    "cataloging": "cataloguing", "defense": "defence", "defenses": "defences",
    "offense": "offence", "offenses": "offences", "gray": "grey", "grays": "greys",
    "grayed": "greyed", "grayish": "greyish", "grayscale": "greyscale",
    "traveled": "travelled", "traveling": "travelling", "traveler": "traveller",
    "travelers": "travellers", "canceled": "cancelled", "canceling": "cancelling",
    "labeled": "labelled", "labeling": "labelling", "modeled": "modelled",
    "modeling": "modelling", "signaled": "signalled", "signaling": "signalling",
    "leveled": "levelled", "leveling": "levelling", "fulfill": "fulfil",
    "fulfills": "fulfils", "fulfillment": "fulfilment", "enroll": "enrol", "enrolls": "enrols",
    "enrollment": "enrolment", "enrollments": "enrolments", "skillful": "skilful",
    "willful": "wilful", "aluminum": "aluminium",
}
# "-or" words write "-our" in NZ, with every ending below ("color", "colors", "colorful").
for us in ["color", "behavior", "favor", "honor", "labor", "neighbor", "flavor", "humor",
           "rumor"]:
    for ending in ["", "s", "ed", "ing", "ful", "less", "al", "ally", "able", "ably", "ite",
                   "ites", "hood", "hoods", "er", "ers"]:
        SPELLING[us + ending] = us[:-2] + "our" + ending

# "-ize", "-ization" and "-yze" forms. NZ writes "-ise", "-isation" and "-yse", except in
# the words in IZE_KEEP, which are spelt with "z" in NZ too ("size", "resize", "seize").
# The list holds whole words, so "synthesize" and "emphasize" are still found.
IZE = re.compile(r"([a-z]+?)(iz|yz)(e|es|ed|ing|er|ers|ation|ations|ational|able)", re.I)
IZE_KEEP = {"size", "resize", "downsize", "upsize", "oversize", "undersize", "outsize",
            "capsize", "seize", "prize", "maize", "baize", "assize", "belize"}

ID = re.compile(r"\b(?:(?:IN|CH)-\d{4}\b|(?:JOB|CAP|DES)-[a-z0-9]+(?:-[a-z0-9]+)*(?:\.R\d+)?"
                r"|R\d+\b)")
PLACEHOLDER = re.compile(r"-(?:0+|x+|name)(?:\.R\d+)?$")
# What, later in the sentence, shows a name next to the ID.
NAMED = re.compile(r"\(|\s·\s|:|^[-–—]\w|\s[-–—]{1,2}\s*\w|—\w")
FIELD = re.compile(r"(?:[-*+]\s+)?(?:Req|Intent|Intents|Change|Changes|Status|Scope|Base|"
                   r"Branch|Ticket|Review|Tests-Locked|Source):")

CONVERSATION = re.compile(
    r"\b(?:as you asked|as requested|as discussed|per your request|the user asked|"
    r"you asked|I['’]ve|I have|we discussed|let me|note to self|in this round|last round)\b",
    re.I)
# These are conversation only at the start of a sentence: "Here is the plan."
OPENER = re.compile(r"[\s\"'*_“]*(here is|here['’]s)\b", re.I)

LIST_ITEM = re.compile(r"\s*(?:[-*+]|\d+[.)])(?:\s+|$)")
INLINE_CODE = re.compile(r"(`+)(.+?)\1")
URL = re.compile(r"<?\bhttps?://[^\s<>()]+>?")
LINK_TARGET = re.compile(r"(?<=\])\([^()\s]*\)")
QUOTED = re.compile(r'"[^"]*"|“[^”]*”')
# A path, a name with "_" or "@", or a file name. Words joined by "/" ("and/or",
# "code/infra-flavoured") are prose, so a path must start with "/" or "~", or have a
# "." in it.
PATH_LIKE = re.compile(r"(?<!\S)(?:[/~]\S*|\S*[\\_@]\S*|\S*\w\.\w\S*)")
SENTENCE_END = re.compile(r"[.!?]+[\"'”’)\]*]*(?=\s|$)")
ABBREVIATION = re.compile(r"\b(?:e\.g|i\.e|vs|cf)\.$", re.I)


def prose_lines(text):
    """Each line of a Markdown file as (number, kind, prose). The kind is one of:
      - "gap": a line that ends a paragraph;
      - "item": the first line of a list item;
      - "heading", "table" or "field": a line that stands alone;
      - "text": any other line.
    Fenced code and front matter other than "description" are gaps. HTML comments are
    removed.
    """
    lines = text.split("\n")
    front = len(lines) > 1 and lines[0].strip() == "---"
    fence, comment, key = None, False, None
    for number, line in enumerate(lines, 1):
        stripped = line.strip()
        if front:
            if number > 1 and stripped in ("---", "..."):
                front = False
            elif number > 1:
                top = re.match(r"([A-Za-z_][\w-]*):(.*)$", line)
                if top:
                    key, line = top.group(1), top.group(2).strip()
                    if line[:1] in "'\"" and line[-1:] == line[:1]:
                        line = line[1:-1]
                if key == "description" and line.strip() not in ("", ">", "|", ">-", "|-"):
                    yield number, "text", line.strip()
                    continue
            yield number, "gap", ""
            continue
        if fence:
            if stripped.startswith(fence) and not stripped.strip(fence[0]):
                fence = None
            yield number, "gap", ""
            continue
        opening = re.match(r"`{3,}|~{3,}", stripped)
        if opening:
            fence = opening.group(0)
            yield number, "gap", ""
            continue
        if comment:
            end = line.find("-->")
            if end < 0:
                yield number, "gap", ""
                continue
            line, comment = line[end + 3:], False
        line = re.sub(r"<!--.*?-->", " ", line)
        if "<!--" in line:
            line, comment = line[:line.index("<!--")], True
        line = re.sub(r"^\s*(?:>\s?)+", "", line)
        stripped = line.strip()
        if not stripped or re.fullmatch(r"[-=*_ ]{3,}", stripped):
            yield number, "gap", ""
        elif re.match(r"#{1,6}(?:\s|$)", stripped):
            yield number, "heading", stripped
        elif stripped.startswith("|"):
            yield number, "table", stripped
        elif FIELD.match(stripped):
            yield number, "field", stripped
        elif LIST_ITEM.match(stripped):
            yield number, "item", LIST_ITEM.sub("", stripped, count=1)
        else:
            yield number, "text", stripped


def blocks(text):
    """The prose as blocks: (kind, [(line number, prose), ...]).

    A block is a paragraph or a list item (kind "text"), or a heading, table row or field
    line on its own.
    """
    found, current = [], None
    for number, kind, line in prose_lines(text):
        if kind == "text" and current:
            current[1].append((number, line))
            continue
        current = None
        if kind in ("text", "item"):
            current = ("text", [(number, line)])
            found.append(current)
        elif kind != "gap":
            found.append((kind, [(number, line)]))
    return found


def blank(pattern, text):
    """The text with each match of the pattern blanked out, keeping every offset."""
    return pattern.sub(lambda m: "_" * len(m.group(0)), text)


def sentences(text):
    """The (start, end) of each sentence in the text."""
    spans, start = [], 0
    for end in SENTENCE_END.finditer(text):
        if ABBREVIATION.search(text, 0, end.end()):
            continue
        spans.append((start, end.end()))
        start = end.end()
    if text[start:].strip():
        spans.append((start, len(text)))
    return spans


def nz_spelling(word):
    """The NZ form of a US word, in the word's case, or None if the word is fine."""
    lower = word.lower()
    if lower in SPELLING:
        fixed = SPELLING[lower]
    else:
        found = IZE.fullmatch(lower)
        if not found:
            return None
        stem, middle, ending = found.groups()
        if middle == "iz" and stem + "ize" in IZE_KEEP:
            return None
        fixed = stem + ("is" if middle == "iz" else "ys") + ending
    if word.isupper():
        return fixed.upper()
    if word[0].isupper():
        return fixed[0].upper() + fixed[1:]
    return fixed


def is_a_list_of_ids(text):
    """True when the text holds only IDs, perhaps after a label ("Capabilities: CAP-x")."""
    rest = re.sub(r"^\s*[A-Z][\w ]*:", "", ID.sub("", text))
    return not re.search(r"[A-Za-z0-9]", re.sub(r"\b(?:and|or)\b", "", rest))


def in_brackets_after_a_name(text, start):
    """True when the ID at start is in brackets that hold only IDs: "the rules (R3, R4)"."""
    opened = text.rfind("(", 0, start)
    if opened < 0 or ")" in text[opened:start]:
        return False
    return is_a_list_of_ids(text[opened + 1:start])


def long_sentences(raw, prose):
    """Rule 1: each sentence over its limit, as (start, end, rule, what, suggestion)."""
    found = []
    for start, end in sentences(prose):
        counted = [w for w in prose[start:end].split() if re.search(r"\w", w)]
        if not counted:
            continue
        first = re.sub(r"[^a-z']", "", counted[0].lower().replace("’", "'"))
        instruction = first in COMMANDS
        limit = INSTRUCTION_LIMIT if instruction else SENTENCE_LIMIT
        if len(counted) <= limit:
            continue
        start += len(prose[start:end]) - len(prose[start:end].lstrip())
        opening = " ".join(raw[start:end].split()[:5]).replace("·", "")
        if instruction:
            what = 'instruction of %d words, starting "%s"' % (len(counted), opening)
            suggestion = "split it: an instruction has %d words or fewer" % limit
        else:
            what = '%d words, starting "%s"' % (len(counted), opening)
            suggestion = "split it: a sentence has %d words or fewer" % limit
        found.append((start, end, RULES[0], what, suggestion))
    return found


def us_spelling(quiet):
    """Rule 2: each US form, as (start, end, rule, what, suggestion)."""
    words = PATH_LIKE.sub(lambda m: " " * len(m.group(0)), quiet)
    found = []
    for word in re.finditer(r"\b[A-Za-z]+\b", words):
        fixed = nz_spelling(word.group(0))
        if fixed:
            found.append((word.start(), word.end(), RULES[1],
                          '"%s" is US spelling' % word.group(0), 'write "%s"' % fixed))
    return found


def ids_alone(prose, quiet):
    """Rule 5: each ID with no name next to it, as (start, end, rule, what, suggestion)."""
    if is_a_list_of_ids(quiet):
        return []
    found = []
    for start, end in sentences(prose):
        for match in ID.finditer(quiet, start, end):
            name, after = match.group(0), quiet[match.end():end]
            before = quiet[match.start() - 1] if match.start() else " "
            quoted_name = re.match(r"\s*[\"“]", prose[match.end():end])
            if (before in "/-." or PLACEHOLDER.search(name) or quoted_name
                    or after.startswith(("*", "-*", "<", "-<"))
                    or in_brackets_after_a_name(quiet, match.start())
                    or NAMED.search(after)):
                continue
            found.append((match.start(), match.end(), RULES[2],
                          '"%s" has no name next to it' % name,
                          'write "%s (<short name>)"' % name))
    return found


def conversation(prose, quiet):
    """Rule 6: each phrase of conversation, as (start, end, rule, what, suggestion)."""
    phrases = [(p.start(), p.end(), p.group(0)) for p in CONVERSATION.finditer(quiet)]
    for start, end in sentences(prose):
        opener = OPENER.match(quiet, start, end)
        if opener:
            phrases.append((opener.start(1), opener.end(1), opener.group(1)))
    return [(start, end, RULES[3], '"%s" tells the conversation' % phrase,
             "state the fact as it is now") for start, end, phrase in phrases]


def check_block(kind, lines):
    """The findings in one block: (first line, last line, rule, what is wrong, suggestion)."""
    raw = " ".join(line for _, line in lines)
    prose = blank(LINK_TARGET, blank(URL, blank(INLINE_CODE, raw)))
    quiet = blank(QUOTED, prose)
    found = us_spelling(quiet) + conversation(prose, quiet)
    if kind == "text":
        found += long_sentences(raw, prose) + ids_alone(prose, quiet)

    starts, at = [], 0
    for number, line in lines:
        starts.append((at, number))
        at += len(line) + 1

    def line_at(offset):
        return [number for begin, number in starts if begin <= offset][-1]

    return [(line_at(start), line_at(max(start, end - 1)), rule, what, suggestion)
            for start, end, rule, what, suggestion in sorted(found)]


def changed_lines(path, base):
    """The numbers of the file's lines that were added or changed since the base."""
    diff = subprocess.run(["git", "diff", "-U0", base + "...HEAD", "--", str(path)],
                          capture_output=True, text=True).stdout
    numbers = set()
    for start, count in re.findall(r"^@@ -\S+ \+(\d+)(?:,(\d+))? @@", diff, re.M):
        numbers.update(range(int(start), int(start) + int(count or 1)))
    return numbers


def check_file(path, since=None):
    """The findings in one file, as output lines."""
    text = Path(path).read_text(errors="replace")
    marked = {n for n, line in enumerate(text.split("\n"), 1) if line.rstrip().endswith(MARKER)}
    changed = changed_lines(path, since) if since else None
    out = []
    for kind, lines in blocks(text):
        for first, last, rule, what, suggestion in check_block(kind, lines):
            span = set(range(first, last + 1))
            if span & marked or (changed is not None and not span & changed):
                continue
            out.append((rule, "%s:%d · %s · %s · %s" % (path, first, rule, what, suggestion)))
    return out


def markdown_files(paths):
    """Each path that is a file, and every .md file in each path that is a folder."""
    files = []
    for path in map(Path, paths):
        if path.is_dir():
            files += sorted(p for p in path.rglob("*.md")
                            if not {".git", "node_modules"} & set(p.parts))
        else:
            files.append(path)
    return files


def changed_files():
    """The .md files changed on this branch against main, or every .md file here."""
    listed = subprocess.run(["git", "diff", "--name-only", "--relative", "main...HEAD"],
                            capture_output=True, text=True)
    if listed.returncode != 0:
        return markdown_files(["."])
    return [Path(name) for name in listed.stdout.splitlines()
            if name.endswith(".md") and Path(name).exists()]


def main(argv):
    args = argv[1:]
    since = None
    if args[:1] == ["--since"]:
        if len(args) < 2:
            print(__doc__)
            return 2
        since, args = args[1], args[2:]
    if args[:1] in (["-h"], ["--help"]):
        print(__doc__)
        return 0
    missing = [p for p in args if not Path(p).exists()]
    if missing:
        print("No such file or folder: %s" % ", ".join(missing))
        return 2

    findings = []
    for path in markdown_files(args) if args else changed_files():
        findings += check_file(path, since)
    for _, line in findings:
        print(line)
    if not findings:
        print("No findings.")
        return 0
    counts = []
    for rule in RULES:
        count = sum(1 for found_rule, _ in findings if found_rule == rule)
        if count:
            counts.append("%d %s" % (count, rule))
    print("%d finding%s: %s." % (len(findings), "" if len(findings) == 1 else "s",
                                 ", ".join(counts)))
    return 1


if __name__ == "__main__":
    sys.exit(main(sys.argv))

### pdlc/bin/make_packets.py

#!/usr/bin/env python3
"""pdlc review packets. Builds one packet per review remit for a change.

Usage:
  python3 pdlc/bin/make_packets.py CH-0001            every remit in pdlc/config.md
  python3 pdlc/bin/make_packets.py CH-0001 --verify   every remit in pdlc/config.md except
                                                      tests, for the verify stage
  python3 pdlc/bin/make_packets.py CH-0001 tests      one remit
  python3 pdlc/bin/make_packets.py IN-0001            the tests packet for the acceptance
                                                      checks of an intent

Each packet is pdlc/changes/<change>/review/<remit>/packet.md. Writing a packet removes
that remit's old result.md, so a result is always about the packet next to it. A packet
holds:
  - the remit, from pdlc/reviews/<remit>.md;
  - the spec:
    - the change spec;
    - the title and summary of the spec it covers (everything above its requirements);
    - the full text of each requirement it lists;
    - every spec it relies on. DES-writing-style goes only to the specification remit,
      because only that remit judges writing;
  - the material: for the tests remit, the check files and nothing else; for every other
    remit, the changed app files and nothing else. The acceptance files of an intent are
    checks, so no packet of a change holds them.
The compliance remit gets a result in place of a packet when its remit file still says
"Rules: none listed yet." and the change touches no dependency file. Then the script
writes result.md with "Result: pass" and the reason, and no reviewer is needed.
The specification packet also holds the writing check and points to the visual review
frames. The writing check is the output of check_writing.py for the lines this change
wrote in its .md files: README, docs, specs and the change spec.

Each packet records the commit that it was made at ("Made at:"). If this remit already
has a result for this change, the new packet is a re-review. The script finds the newest
result in the folder, or else in git. A re-review packet adds a "Re-review" section:
  - "Earlier review:", the commit that the earlier review judged: for tests, the lock in
    its packet; for every other remit, its "Made at";
  - the problems from the earlier result;
  - the diff of the material since that commit.
On a re-review, the writing check covers only the lines changed since that commit, and
the frame list marks each frame that did not change.

The packet for the acceptance checks of an intent is
pdlc/acceptance/<intent>/review/tests/packet.md. It holds the tests remit, the intent, the
full text of each requirement that the intent lists, the "Interface" of each change of
the intent, the specs that those changes rely on (but not DES-writing-style), and the
acceptance file that the intent names under "Acceptance-File:". It also holds the diff of
each acceptance file of an earlier intent that the lock commit changed. It holds no app
code and no component checks. A re-review starts from the lock in the earlier packet
("Acceptance-Locked:").

Run it from the project root, on the change's branch. For an intent, run it on the newest
branch of the intent.
"""
import re
import subprocess
import sys
from pathlib import Path

DEFAULT_REMITS = ["tests", "specification", "security", "quality", "compliance", "privacy"]
KINDS = {"JOB": "jobs", "CAP": "capabilities", "DES": "design"}
WRITING_CHECK = Path(__file__).parent / "check_writing.py"
# Files that declare dependencies. When a project lists no compliance rules, a change that
# touches none of these files has nothing for the compliance remit to judge.
DEPENDENCY_FILES = re.compile(
    r"(^|/)(requirements[^/]*\.txt|pyproject\.toml|setup\.py|setup\.cfg|Pipfile(\.lock)?|"
    r"package(-lock)?\.json|yarn\.lock|pnpm-lock\.yaml|go\.(mod|sum)|Cargo\.(toml|lock)|"
    r"Gemfile(\.lock)?|pom\.xml|build\.gradle(\.kts)?|composer\.(json|lock)|[^/]*\.csproj)$")
NO_RULES = "Rules: none listed yet."
# A file name that holds the word "acceptance" and an intent ID is an acceptance file, also
# when pdlc/config.md has no "acceptance file:" line.
ACCEPTANCE_NAME = re.compile(r"(?=.*acceptance)(?=.*(?<![a-z0-9])in[-_]?\d{4}(?!\d))", re.I)


def section(text, title):
    match = re.search(r"^## %s\s*$(.*?)(?=^## |\Z)" % re.escape(title), text, re.M | re.S)
    return match.group(1) if match else ""


def field(text, name):
    """A header field of a change spec or intent, such as Status or Branch. The value is
    bare: "IN-0001 (poll-input-errors)" gives "IN-0001", and "`pdlc/CH-0001-x`" gives
    "pdlc/CH-0001-x"."""
    match = re.search(r"\b%s:[ \t]*([^·\n]*?)[ \t]*(?:·|$)" % name, text, re.M)
    if not match:
        return None
    value = match.group(1).replace("`", "")
    return re.sub(r"\s+\(.*\)$", "", value).strip()


def git(root, *args):
    return subprocess.run(["git", *args], cwd=root, capture_output=True, text=True).stdout


def show(root, ref, path):
    """A file as it is at a commit, or None if git cannot find it there."""
    out = subprocess.run(["git", "show", "%s:%s" % (ref, path)], cwd=root,
                         capture_output=True, text=True)
    return out.stdout if out.returncode == 0 else None


def remits(root):
    config = root / "pdlc" / "config.md"
    text = config.read_text() if config.exists() else ""
    line = re.search(r"^- remits:\s*(.+)$", section(text, "Reviews"), re.M)
    if not line:
        return DEFAULT_REMITS
    return [r.strip() for r in line.group(1).split(",") if r.strip() and r.strip() != "none"]


def acceptance_file(root):
    """A regex for the path of an acceptance file, from "acceptance file:" in pdlc/config.md,
    or None. "{intent}" in the path stands for any intent ID."""
    config = root / "pdlc" / "config.md"
    text = config.read_text() if config.exists() else ""
    line = re.search(r"^- acceptance file:\s*`([^`]+)`", text, re.M)
    if not line or "{intent}" not in line.group(1):
        return None
    parts = line.group(1).strip("/ ").split("{intent}")
    return re.compile("^%s$" % r"IN[-_]?\d+".join(re.escape(part) for part in parts), re.I)


def is_acceptance(path, pattern):
    """True when the path is the acceptance file of an intent."""
    return bool((pattern and pattern.match(path)) or ACCEPTANCE_NAME.match(path.rsplit("/", 1)[-1]))


def record(text, name):
    """The value of a line such as "Acceptance-Locked: 1a2b3c4" in the "Acceptance checks"
    section of an intent: the last such line, without backticks. None if there is none."""
    found = re.findall(r"^%s:[ \t]*`?([^`\s]+)`?" % re.escape(name), section(text, "Acceptance checks"), re.M)
    return found[-1] if found else None


def compliance_applies(remit_text, changed):
    """False when the project lists no compliance rules and no dependency file changed."""
    return NO_RULES not in remit_text or any(DEPENDENCY_FILES.search(f) for f in changed)


def spec_file(root, spec_id):
    return root / "pdlc" / "specs" / KINDS[spec_id.split("-", 1)[0]] / (spec_id + ".md")


def requirement_text(root, req_id):
    path = spec_file(root, req_id.rsplit(".", 1)[0])
    if not path.exists():
        return "(%s not found)" % req_id
    text = path.read_text()
    match = re.search(r"^### %s\b.*?(?=^### |^## |\Z)" % re.escape(req_id), text, re.M | re.S)
    return match.group(0).strip() if match else "(%s is not in its spec)" % req_id


def spec_head(root, spec_id):
    """A spec's title, summary and code map: everything above its '## Requirements'."""
    path = spec_file(root, spec_id)
    if not path.exists():
        return "(%s not found)" % spec_id
    return re.split(r"^## Requirements\b", path.read_text(), maxsplit=1, flags=re.M)[0].strip()


def fence(text):
    return "````\n" + text.rstrip() + "\n````"


def material(root, base, files, title):
    parts = ["## %s\n" % title]
    if not files:
        return parts[0] + "\nNone changed.\n"
    parts.append("### Diff against %s\n\n%s\n" % (base, fence(git(root, "diff", base + "...HEAD", "--", *files))))
    for name in files:
        path = root / name
        body = path.read_text(errors="replace") if path.exists() else "(deleted)"
        parts.append("### %s\n\n%s\n" % (name, fence(body)))
    return "\n".join(parts)


def earlier_review(root, target, remit, lock="Tests-Locked"):
    """The commit that an earlier review of this remit judged, and the problems that it
    found. The newest result is in the folder, or else in the newest commit that has it.
    None when there is no earlier result, or its packet does not say what it judged. For
    the acceptance checks of an intent, the lock is "Acceptance-Locked"."""
    result, packet = target / "result.md", target / "packet.md"
    found = None
    if result.exists():
        found = result.read_text(), (packet.read_text() if packet.exists() else "")
    else:
        path = result.relative_to(root).as_posix()
        for sha in git(root, "log", "--format=%H", "--", path).split():
            text = show(root, sha, path)
            if text is not None:
                found = text, show(root, sha, packet.relative_to(root).as_posix()) or ""
                break
    if not found:
        return None
    text, old_packet = found
    locks = re.findall(r"^%s:\s*([0-9a-f]{7,40})\b" % lock, old_packet, re.M)
    made = re.findall(r"^Made at:\s*([0-9a-f]{7,40})\b", old_packet, re.M)
    shas = (locks[-1:] if remit == "tests" else []) + made[:1]
    if not shas:
        return None
    problems = re.search(r"^[#*_ \t]*Problems\b[*_:]*(.*?)(?=^[^\s-]|\Z)", text,
                         re.M | re.S | re.I)
    problems = problems.group(1).strip() if problems else ""
    if problems.lower().strip("-. ") in ("", "none"):
        # If this cannot find the problems of a failed result, the whole result goes in.
        # Thus, no problem is lost.
        passed = re.match(r"\s*Result:\s*pass\b", text, re.I)
        problems = "none" if passed else fence(text)
    return shas[0], problems


def re_review(remit, sha, problems, diff):
    """The section that makes a packet a re-review."""
    judged = "the checks locked at" if remit == "tests" else "this change at"
    rule = ("Do not raise a new problem on material that did not change. This rule also applies"
            "\nto a problem that the earlier review missed.")
    if remit == "tests":
        rule += ('\nWrite a "Wrong versions" line only for each check that changed. If no check'
                 '\nchanged, write "none" under "Wrong versions".')
    return "\n".join([
        "## Re-review\n",
        "Earlier review: %s\n" % sha,
        "An earlier review of this remit judged %s %s. Judge only these two things:\n"
        % (judged, sha[:12]),
        '1. Each earlier problem below. If the problem is not fixed, list it again under'
        ' "Problems".',
        "2. The changes since the earlier review, in the diff below. List a new problem only",
        "   where a changed line causes the problem.\n",
        rule + "\n",
        "### Earlier problems\n", problems + "\n",
        "### Changes since the earlier review\n",
        (fence(diff) if diff.strip() else "Nothing changed.") + "\n"])


def diff_since(root, sha, files):
    """The diff of the files from the commit to HEAD. None if git cannot make it."""
    if not files:
        return ""
    out = subprocess.run(["git", "diff", sha, "HEAD", "--", *files], cwd=root,
                         capture_output=True, text=True)
    return out.stdout if out.returncode == 0 else None


def unchanged_since(root, sha, path):
    """True when the file is the same now as at the commit."""
    then = subprocess.run(["git", "rev-parse", "-q", "--verify", "%s:%s" % (sha, path)],
                          cwd=root, capture_output=True, text=True).stdout.strip()
    now = git(root, "hash-object", path).strip()
    return bool(then) and then == now


def writing_check(root, base, files):
    """The packet section with the writing check of the lines this change wrote."""
    title = "## Writing check\n\n"
    if not files:
        return title + "No text files changed.\n"
    done = subprocess.run([sys.executable, str(WRITING_CHECK), "--since", base, *files],
                          cwd=root, capture_output=True, text=True)
    return title + ("`pdlc/bin/check_writing.py --since %s` on %s:\n\n%s\n"
                    % (base, ", ".join(files), fence(done.stdout + done.stderr)))


def intent_packet(root, intent):
    """The tests packet for the acceptance checks of an intent."""
    found = sorted((root / "pdlc" / "inbox").glob(intent + "-*.md"))
    if not found:
        print("No intent found for %s" % intent)
        return 1
    text = found[0].read_text()
    checks, lock = record(text, "Acceptance-File"), record(text, "Acceptance-Locked")
    if not checks or checks == "none":
        print("%s names no Acceptance-File, so it has no acceptance checks to review" % intent)
        return 1
    if not lock or not re.match(r"[0-9a-f]{7,40}$", lock):
        print("Lock the acceptance checks of %s first: its Acceptance-Locked has no hash" % intent)
        return 1

    reqs = re.findall(r"\b((?:JOB|CAP|DES)-[a-z0-9-]+\.R\d+)\b", section(text, "Requirements"))
    changes, relies = [], []
    for change in dict.fromkeys(re.findall(r"\bCH-\d+\b", section(text, "Changes"))):
        specs = sorted((root / "pdlc" / "changes").glob(change + "-*/change.md"))
        spec = specs[0].read_text() if specs else ""
        title = re.search(r"^# .*$", spec, re.M)
        changes.append("### %s\n\n%s\n" % (title.group(0)[2:] if title else change,
                                            fence(section(spec, "Interface").strip() or "(no Interface)")))
        relies += re.findall(r"\b((?:JOB|CAP|DES)-[a-z0-9-]+)\b", section(spec, "Relies on"))

    target = root / "pdlc" / "acceptance" / found[0].stem / "review" / "tests"
    earlier = earlier_review(root, target, "tests", lock="Acceptance-Locked")
    diff = diff_since(root, earlier[0], [checks]) if earlier else None
    earlier = earlier + (diff,) if diff is not None else None
    remit = root / "pdlc" / "reviews" / "tests.md"
    path = root / checks
    out = ["# Review packet · %s · tests (acceptance checks)\n" % found[0].stem,
           "Judge only what is in this packet. Write your result next to it, in result.md.\n",
           "Made at: %s\n" % git(root, "rev-parse", "HEAD").strip(),
           "Acceptance-Locked: %s\n" % lock,
           "These are the acceptance checks of an intent. Judge them by the section \"Acceptance",
           "checks of an intent\" of the remit below, and by its \"Wrong versions\".\n"]
    if earlier:
        out.append(re_review("tests", *earlier))
    out += [(remit.read_text() if remit.exists() else "# Remit: tests\n").strip() + "\n",
            "## The intent\n", fence(text), "\n## The requirements, in full\n"]
    out += [requirement_text(root, r) + "\n" for r in dict.fromkeys(reqs)]
    out.append("## The interface of each change of the intent\n")
    out += changes
    out.append("## Specs the changes rely on\n")
    for spec_id in dict.fromkeys(relies):
        if spec_id != "DES-writing-style":
            spec = spec_file(root, spec_id)
            out.append("### %s\n\n%s\n" % (spec_id, fence(spec.read_text()) if spec.exists() else "(not found)"))
    out += ["## The acceptance checks\n", "### %s\n" % checks,
            fence(path.read_text(errors="replace") if path.exists() else "(missing)") + "\n"]
    # A check of a requirement that this intent changes or retires leaves the acceptance file
    # of the earlier intent. The lock commit holds each such removal.
    pattern = acceptance_file(root)
    touched = [f for f in git(root, "diff", "--name-only", lock + "~1", lock).splitlines()
               if f != checks and is_acceptance(f, pattern)]
    out.append("## Checks removed from earlier intents\n")
    out.append(fence(git(root, "diff", lock + "~1", lock, "--", *touched)) + "\n" if touched

    target.mkdir(parents=True, exist_ok=True)
    (target / "packet.md").write_text("\n".join(out) + "\n")
    (target / "result.md").unlink(missing_ok=True)
    print("wrote %s" % (target / "packet.md").relative_to(root).as_posix())
    return 0

// pdlc visual review: plays a short script and records it as a GIF plus PNG frames.
//
// Usage: node pdlc/bin/record_gif.mjs <script.json> <out-dir>
//
// The script is JSON:
// {
//   "kind": "web" | "terminal",
//   "title": "CH-0001 · Spanish greeting",
//   "base_url": "http://localhost:3000",       (web only)
//   "start": "node server.js",                 (optional: started first, stopped after)
//   "width": 1000, "height": 640,              (optional)
//   "steps": [
//     { "caption": "JOB-x.R1 · Given …, when …, then …", "goto": "/" },
//     { "type": ["#title", "buy milk"] }, { "press": "Enter" }, { "click": "#add" },
//     { "wait": 500 },
//     { "caption": "CAP-x.R2 · …", "run": "node src/cli.js Ana --lang es" }   (terminal)
//   ]
// }
//
// Every step makes one frame. A caption stays until the next step sets a new one.
// A terminal shows each command's output and errors in order, and scrolls like a real
// one: every frame shows the newest lines.
//
// A frame must show what its caption claims. The recording fails, naming the step, when:
//   - a frame is blank: almost every pixel is one colour;
//   - a step that should change the screen doesn't. That is a click, typing or a key press
//     that leaves the page as it was, or a command that prints nothing.
// After a click, typing or a key press, the recorder waits up to 5 s for the page to change
// and settle. Then the frame shows the result, not the page before it. A step whose
// acceptance line says nothing changes sets "unchanged": true. If a check fails, the
// recorder writes no review.gif.

  let last = await look(page);

    await page.waitForTimeout(150);
    const next = await look(page);

// True when fewer than 1 pixel in 10,000 differs clearly from the most common colour.
function isBlank(png) {
  const { data, width: w, height: h } = PNG.sync.read(png);
  const counts = new Map();
  for (let i = 0; i < data.length; i += 4) {
    const key = (data[i] << 16) | (data[i + 1] << 8) | data[i + 2];
    counts.set(key, (counts.get(key) || 0) + 1);
  }
  let top = 0;
  let most = 0;
  for (const [key, n] of counts) if (n > most) { most = n; top = key; }
  const [r, g, b] = [top >> 16, (top >> 8) & 255, top & 255];
  let ink = 0;
  for (let i = 0; i < data.length; i += 4) {
    if (Math.abs(data[i] - r) + Math.abs(data[i + 1] - g) + Math.abs(data[i + 2] - b) > 48) ink++;
  }
  return ink * 10000 < w * h;
}

#!/usr/bin/env python3
"""pdlc merge records. Keeps the statuses on main true after merges.

Run it on main, before any work. It:
  - sets each change whose branch has merged into main to "merged";
  - sets each intent whose changes have all merged to "done";
  - commits those files on main, only if something changed, and prints what changed.

It never switches branches, and never commits anywhere but main.

Usage:
  python3 pdlc/bin/record_merges.py

Run it from the project root. Exit code 0 means main's records are up to date.
"""
import re
import subprocess
import sys
from pathlib import Path


def git(root, *args):
    return subprocess.run(["git", *args], cwd=root, capture_output=True, text=True)


def section(text, title):
    """The text under a '## title' heading, up to the next '## ' heading."""
    match = re.search(r"^## %s\s*$(.*?)(?=^## |\Z)" % re.escape(title), text, re.M | re.S)
    return match.group(1) if match else ""


def field(text, name):
    """A header field of a change spec or intent, such as Status or Branch. The value is
    bare: "IN-0001 (poll-input-errors)" gives "IN-0001", and "`pdlc/CH-0001-x`" gives
    "pdlc/CH-0001-x"."""
    match = re.search(r"\b%s:[ \t]*([^·\n]*?)[ \t]*(?:·|$)" % name, text, re.M)
    if not match:
        return None
    value = match.group(1).replace("`", "")
    return re.sub(r"\s+\(.*\)$", "", value).strip()


def with_status(text, status):
    """The text with its header's status set to this one."""
    return re.sub(r"(\bStatus:[ \t]*)[^·\n]*?([ \t]*(?:·|$))", r"\g<1>%s\g<2>" % status,
                  text, count=1, flags=re.M)


def has_merged(root, branch):
    """True when every commit on the branch is in main."""
    return git(root, "merge-base", "--is-ancestor", branch, "main").returncode == 0


def main(argv, root=Path(".")):
    here = git(root, "rev-parse", "--abbrev-ref", "HEAD").stdout.strip()
    if here != "main":
        print("Run this on main, not on %s. Nothing changed." % (here or "no branch"))
        return 1

    touched, intents, statuses = [], set(), {}
    for spec in sorted((root / "pdlc" / "changes").glob("CH-*/change.md")):
        text = spec.read_text()
        change = "-".join(spec.parent.name.split("-", 2)[:2])
        status, branch = field(text, "Status"), field(text, "Branch")
        if status not in ("merged", "cancelled") and branch not in (None, "", "none") \
                and has_merged(root, branch):
            spec.write_text(with_status(text, "merged"))
            touched.append(spec)
            intents.add(field(text, "Intent"))
            print("%s is now merged (was %s)" % (change, status))
            status = "merged"
        statuses[change] = status

    for path in sorted((root / "pdlc" / "inbox").glob("IN-*.md")):
        text = path.read_text()
        changes = re.findall(r"\bCH-\d+\b", section(text, "Changes"))
        status = field(text, "Status")
        if changes and status != "done" and all(statuses.get(c) == "merged" for c in changes):
            path.write_text(with_status(text, "done"))
            touched.append(path)
            intent = "-".join(path.name.split("-", 2)[:2])
            intents.add(intent)
            print("%s is now done (was %s)" % (intent, status))

    if not touched:
        print("Nothing to record: main is up to date.")
        return 0
    message = "Record merges\n\nIntent: %s\n" % ", ".join(sorted(i for i in intents if i))
    files = [p.relative_to(root).as_posix() for p in touched]
    out = git(root, "commit", "-q", "-m", message, "--", *files)
    if out.returncode != 0:
        print("Could not commit on main: %s" % (out.stderr.strip() or out.stdout.strip()))
        return 1
    print("Committed on main: Record merges")
    return 0


if __name__ == "__main__":
    sys.exit(main(sys.argv))

# Port: checks

The checks port runs the checks of the project. A check is an item that proves a
requirement with a pass or a fail. A check can be a test, a script, a lint rule, an eval,
or a query.

## Operations

- **run all**: run all the checks. Return pass or fail, and the output of each check that
  failed.
- **run for requirement**: the input is a requirement ID. Run only the checks whose names
  carry that ID. Return pass or fail for each check.
- **find**: the input is a requirement ID. List the checks that carry that ID.
- **run acceptance**: the input is an intent ID. Run the checks in the acceptance file of
  that intent. Return pass or fail for each check, and the output of each check that
  failed.
- **run earlier acceptance**: the input is an intent ID. Run the acceptance files of each
  other intent whose acceptance checks passed already. The `Acceptance-Passed:` line of
  such an intent holds a hash. Return pass or fail for each check.

The **run all** operation does not run an acceptance file. Thus, the acceptance checks of
an open intent can fail, and the other checks stay green.

## Success

If a check is known to fail, the port reports that check as failed. If a requirement has
no checks, the port reports that the requirement has no checks. The port does not report
that requirement as a pass.

If an intent has no acceptance file, **run acceptance** reports "no acceptance checks
found". If the acceptance checks of no other intent passed yet, **run earlier acceptance**
reports "none", and that is a pass.

## Conformance check

1. Add a check that always fails, with the made-up ID `CAP-conformance.R1` in its name.
2. Run for that requirement. The port reports one failed check.
3. Run for `CAP-conformance.R2`. The port reports "no checks found".
4. Remove the check.
5. Write an acceptance file for the made-up intent `IN-9999`, with one check that always
   fails. Run all. The run does not include that check.
6. Run acceptance for `IN-9999`. The port reports one failed check.
7. Remove the acceptance file.

### pdlc/reviews/tests.md
```
# Remit: tests

Default: yes

You judge the checks, not the code. You do not see the code. The list below is for the
component checks of a change. For the acceptance checks of an intent, the section
"Acceptance checks of an intent" gives the differences.

- Each acceptance line in the change spec has at least one check. The exception is a
  requirement marked `(retire)`: its acceptance lines get no check, and each check that
  only proved them is gone.
- The name of each check contains its requirement ID.
- Each check tests what the acceptance line says, through the "Interface" in the change
  spec. The check does not depend on the internal structure of the code.
- A component check is permitted to prepare state directly, for example with a fixture
  file. But the check reads each result through the interface, unless the requirement is
  about the stored form.
- A check proves each line at the surface that the line names. A line where the person
  clicks needs a check that clicks and reads what shows. A check of a helper below that
  surface is not sufficient alone.
- If a line depends on the current date or time, its check sets the clock through a seam
  at that same surface. A check that runs a command sets the clock with the environment
  variable or flag of the command. Each of these is a problem:
  - Using the real clock, or setting the time only on a helper below the surface.
  - Leaving a line to manual checks when a stand-in seam could reach the surface.
- Each check can fail. It fails on a plausible wrong version of the code (see "Wrong
  versions"). A check that passes, whatever the code does, does not count.
- A correct app passes each check. A fake that stands in for something real must use the
  names and the behaviour of the real thing. Then the check does not prove only the fake.
- No check can hang. Anything that waits for the app has a time limit.
- Each error code that the Interface lists has a check that expects that exact code.
- The checks control time, randomness, and vendors only through the "Test seams" of the
  Interface.
- The checks are sufficiently clear that a failure tells you what broke.

## Wrong versions

For each check, name one plausible wrong version of the code. Decide whether the check
fails on that version. Write one line for each check under "Wrong versions" in your
result: the check, the wrong version, and `fails` or `passes`. A check that passes a
plausible wrong version is a problem. Name the value or line that catches the wrong
version. On a re-review, write a line only for each check that changed since the earlier
review.

Look for these traps:

- Examples that also fit a wrong rule. These are common cases:
  - A rule about order, tested with items that are already in that order or in
    alphabetical order.
  - Values that come out the same if the code rounds up, rounds down, or rounds to the
    nearest value.
  - Text that is already in the case that the rule asks for.
- A limit that the check does not test exactly at the edge and one past the edge. For "at
  most 20", the value 20 passes and the value 21 fails. Values near the edge prove nothing
  about the edge.
- A rule about every member of a class that the check tests without a non-member.
  "Any other value is an error" needs a value close to an allowed value, not only a few
  far-off values. A close value differs by its case, a space, or a prefix. "Only the
  owner may" needs a person who is not the owner.

## Acceptance checks of an intent

The packet holds the intent, the full text of its requirements, and the "Interface" of
each of its changes. Judge the acceptance checks by the list at the top, with these
differences:

- Each acceptance line of each requirement that the intent lists has at least one check. A
  `retiring` requirement has no check.
- Each check uses only what a user uses: commands, HTTP requests, pages, or the public
  functions of a library. A check can use each feature of the intent, and each feature
  that exists already.
- No check reads or writes stored data directly. A check that opens a saved file or
  queries a store is a problem.
- A check can leave the acceptance file of an earlier intent only when the check proved a
  requirement that this intent changes or retires. Then a check in this file proves the
  new line. Any other removal is a problem.
- Each check fails until the last change of the intent is built. That is not a problem.

Write "Wrong versions" for the acceptance checks in the same way as for other checks.

example), write the ID with underscores instead: `test_CAP_email_R3_sends_from_a_template`.
The two forms count as the same ID. Use only one form in each project.

Lay checks out the same way everywhere:

- Put new check files in the check folder (`tests/` in a project that had none). Name
  each file after the spec it proves, in a form the runner finds: `test_CAP_email.py`,
  `CAP-email.test.js`.
- Inside a file, make one group per requirement (a test class or a `describe` block).
  Name the group with the requirement ID: `class CAP_email_R3(unittest.TestCase)`,
  `describe("CAP-email.R3", ...)`.
- Each check's name still starts with the ID, then says what it proves.

The acceptance checks of an intent go in one file for each intent, at the path of
"acceptance file" in `pdlc/config.md`. The name of the file holds the word "acceptance"
and the intent ID, for example `tests/acceptance_IN_0012.py` or
`acceptance/IN-0012.acceptance.js`. The "all" command does not run such a file. Inside the
file, make one group for each requirement, and start each check name with the requirement
ID.

## Why

The trace from a requirement to its checks is only as good as this naming. Thus, the
naming must be simple and the same everywhere.

# DES-writing-style · How pdlc writes

Status: agreed · Default: yes · Ask at init: yes

## Rule

This rule is a copy of `WRITING-GUIDELINES.md` from the pskills repository.

These guidelines apply to all writing in this repository. They also apply to all text that
an agent writes when it uses the skills in this repository. They have four parts:

1. Part 1 gives the rules of ASD-STE100 Simplified Technical English (STE) in short form.
2. Part 2 gives two more rules: the local-references rule and the described-IDs rule.
3. Part 3 tells you how to apply the rules to each type of text.
4. Part 4 tells you how to examine your text against the rules.

### Where these guidelines apply

Use these guidelines for all of these types of text:

- The replies that an agent writes to the user in a conversation.
- Skills: the `SKILL.md` file, its reference files, and its templates.
- Agent definitions, system prompts, and the prompts that an agent writes for other agents.
- The documents that a skill or an agent writes: specs, designs, plans, reports, and web
  pages.
- Commit messages, pull request text, and code comments.

These items are not prose. Do not change them to obey the rules:

- Code, commands, file paths, and identifiers.
- Error codes, field names, and values.
- Header fields, for example `Intent:`, `Scope:`, `Status:`, `Branch:`, and `Base:`. A
  script reads each value. Thus, a header field holds only the bare value, with no name
  and no backticks. Write `Intent: IN-0001`, not `Intent: IN-0001 (poll-input-errors)`.
- Quoted text. For example, the words of a user, or the trigger phrases in the description
  of a skill.
- The names of products, organisations, and published works.

### Part 1: STE rules

STE is a controlled language for technical text. The standard has 53 rules in nine
sections, and a dictionary of approved words. This part gives the rules in short form,
with the rule numbers of the standard. This repository does not contain the dictionary.
Part 4 tells you how to get the dictionary and how to use it.

#### Words (STE section 1)

- **1.1** Use approved words, technical nouns, and technical verbs.
- **1.2 to 1.4** Use an approved word only as its approved part of speech. Use the word
  only with its approved meaning and in its approved forms. For example, "check" is
  approved as a noun. As a verb, write "make sure that".
- **1.5, 1.6, 1.8 to 1.10** Technical nouns are the names of items in your subject.
  Examples in software are "commit", "branch", "file", "schema", and "pull request". Use
  the terms that your project uses. Select short terms. Do not use slang or jargon.
- **1.7** Do not use a technical noun as a verb. For example, do not write "action the
  ticket". Write "close the ticket".
- **1.11** Use one technical noun for one item. Do not use a different noun for the same
  item in a different part of the text.
- **1.12, 1.13** Technical verbs are the actions in your subject. In software, "commit",
  "merge", "deploy", "parse", and "click" are technical verbs. Do not use a technical verb
  as a noun. Write "merge the branch", not "do a merge of the branch".
- **1.14** Use New Zealand English spelling, for example "behaviour", "colour", and
  "organise". STE uses American English unless your own rules give a different standard.
  These guidelines give New Zealand English. Do not change the spelling of code, field
  names, or quoted text.

#### Multi-word nouns (STE section 2)

- **2.1** Do not write a multi-word noun of more than three words. For example, do not
  write "test result cache file path". Write "the path of the cache file for test
  results".
- **2.2** If a technical noun has more than three words, write it in full one time. Then
  use a shorter form, or join the words with hyphens.

#### Verbs (STE section 3)

- **3.1, 3.2** Use only these verb forms:
  - The infinitive: "to run".
  - The imperative: "Run the tests."
  - The simple present, the simple past, and the simple future: "runs", "ran", "will run".
  - The past participle as an adjective: "the merged branch".
- **3.3** Use the past participle as an adjective, for example "the merged branch".
- **3.4** Do not use auxiliary verbs to make complex verb constructions. For example, do
  not write "the file should have been updated". Write "update the file".
- **3.5** Use the "-ing" form of a verb only in a technical noun, for example "load
  balancing". Do not write "When running the tests, read the log". Write "When you run
  the tests, read the log".
- **3.6** Use the active voice. In descriptive text, you can use the passive voice only
  when you do not know who or what does the action.
- **Modal verbs (3.2, 3.4).** STE has "must" and "can". It does not have "should" or "may".
  Keep the strength of the original text:
  - A rule that always holds: write "must" or "must not".
  - Advice or a default: write "Try to …" or "Usually, …". Do not write "must".
  - A permission: write "is permitted to …". Write "can" for an ability.
  - The word "never": write "Do not …".
- **3.7** Use a verb to show an action, not a noun. Write "install the package", not "do
  the installation of the package".

#### Sentences (STE section 4)

- **4.1** Write short and clear sentences. Give one topic in each sentence. Give accurate
  facts, not abstract statements. For example, do not write "Large inputs change the run
  time". Write "When the input has more than 1,000 rows, the run time increases".
- **4.2** Do not omit words to make a sentence shorter. Do not omit articles, verbs, or
  subjects. Do not use contractions. Write "do not", not "don't".
- **4.3** Use a vertical list for complex text.
- **4.4** Use connecting words to connect related sentences, for example "and", "but",
  "then", "thus", and "as a result".
- **4.5** When applicable, put "the", "a", "an", "this", or "these" before a noun.

#### Instructions (STE section 5)

STE calls this type of text a procedure.

- **5.1** Write a maximum of 20 words in each instruction.
- **5.2** Write only one instruction in each sentence, unless the actions occur at the
  same time.
- **5.3** Write instructions in the imperative: "Run the tests."
- **5.4** If the reader must know a condition first, start with the condition. Put a comma
  after the condition: "If the tests fail, stop."
- **5.5** Use a note only to give information, not to give an instruction.

#### Descriptive text (STE section 6)

Descriptive text gives information, not instructions. Do not use the imperative in
descriptive text.

- **6.1** Give information gradually. Give the primary point first, then the details.
- **6.2** Use key words and headings to show the structure of the text.
- **6.3** Write a maximum of 25 words in each descriptive sentence.
- **6.4 to 6.6** Use paragraphs to show related information. Give each paragraph only one
  topic. Write a maximum of six sentences in each paragraph.

#### Safety instructions (STE section 7)

In software, a safety instruction tells the reader about an action that can cause loss of
data or other damage. Examples are a force push, a deleted table, and a message to other
persons.

- **7.1** Start with a word that shows the level of risk. Write "Warning" for a risk to
  persons. Write "Caution" for a risk to data or equipment.
- **7.2** Then give a clear command or condition.
- **7.3** Then give the risk or the possible result.

For example: "Caution: Do not force push to a shared branch. A force push can erase the
commits of other persons."

#### Punctuation and word count (STE section 8)

- **8.1** Do not use the semicolon. Write two sentences.
- **8.2** Use a hyphen to join words that are directly related, for example "read-only".
- **8.3** Use parentheses for references, identifiers, abbreviations, short explanations,
  and alternatives.
- **8.4** In a vertical list, a colon ends a sentence for the word count.
- **8.5 to 8.7** For the word count, count each of these items as one word:
  - Text in parentheses.
  - A number, or a number with its unit.
  - An abbreviation or an identifier.
  - Quoted text.
  - A title or a heading.
  - A proper noun.
  - A hyphenated word.

#### Writing practices (STE section 9)

- **9.1** If you cannot replace a word with an approved word, write the sentence again
  with a different structure.
- **9.2** Use each word correctly.
- **9.3** Do not use phrasal verbs. For example, write "prepare" or "configure", not "set
  up". Write "find", not "find out".
- **9.4** Use the same terms and the same style in all of the text.

#### General recommendations (STE)

- **GR-1** Write "that" after verbs such as "make sure", "show", and "recommend". For
  example: "Make sure that the tests pass."
- **GR-2** When you use "with", read the sentence again. Make sure that the sentence has
  only one meaning.
- **GR-3, GR-4** If a pronoun can refer to more than one noun, write the noun. The
  local-references rule in Part 2 makes this rule stricter.
- **GR-6** Do not use Latin abbreviations. Write "for example", not "e.g.". Write "that
  is", not "i.e.". Do not write "etc.".
- **GR-7** Use gender-neutral language. Use "they" for a person whose pronouns you do not
  know.
- **GR-8** Use the possessive form, for example "the user's file", only when you are sure
  that it is correct.

### Part 2: Two more rules

These two rules apply together with the STE rules.

#### The local-references rule

The reader must not look back far to find what a word refers to.

- A pronoun ("it", "they", "this", "that", "these", "those") must refer to a noun in the
  same paragraph. A short noun, for example "the file" or "the change", must also refer
  to a noun in the same paragraph.
- Only one noun in that paragraph can match the reference. If two nouns can match, write
  the full noun.
- At the start of a paragraph, a list item, a table cell, or a reply, write the full noun.
  Do not use "It", "This", or "They" to refer to an earlier paragraph.
- A heading does not give a noun to the text below the heading. Under the heading
  "OutboxAccess", do not start with "It stores". Write "OutboxAccess stores".
- In a conversation, each reply must make sense alone. Do not write "the PR" or "the
  second option" to refer to an earlier reply. Write the name or the full description.

For example, do not write: "The run found a problem in the template and in the checker.
It is now correct." Write: "The run found a problem in the template and in the checker. I
corrected the template."

#### The described-IDs rule

An ID is a short code that names an item, for example "B2", "R3", "V1", "UC2", "PR #6",
"task #4", or a commit hash. An ID without a description makes the reader look back.

- Each time that you write an ID, write a short description of the item in the same
  sentence. For example: "B2 (cache the results)".
- When the reader must select an alternative, give each alternative its ID and its
  description in the question. Do not ask "B1, B2, or B3?".
- In a table, a row that gives the ID and the description is sufficient for that row.
- A header field, for example `Intent: IN-0001`, holds only the ID. Do not add a
  description to the ID there.
- Make each description short and simple: two to eight words.
- If the ID is not necessary for the reader, do not use the ID. Use the description only.

For example, do not write: "Do you want B1 or B3?" Write: "Do you want B1 (keep the
cache) or B3 (remove the cache)?"

### Part 3: How to apply the rules

#### Replies to the user

- Give the answer or the result first. Then give the details.
- Use plain words, and give the context that the reader must have.
- Use short sentences. Use a list for three or more items. Do not write a paragraph when
  sentences in a list are sufficient.
- Write only about the topic. Do not add text that does not relate to the topic.
- Make each reply clear alone. Obey the local-references rule.
- When you ask a question with alternatives, obey the described-IDs rule.

#### Skills, agent definitions, and prompts

- If a skill gives an exact output format, the format has priority over these
  guidelines. For example, a skill can tell an agent to write one sentence for each
  option. Then the agent writes one sentence, also when the sentence has two topics.
- Write each step in the imperative. Write one instruction in each sentence.
- Put the condition first: "If the suite exists, load the suite."
- Give numbers to the steps of a procedure.
- Write the purpose of a skill, and other descriptive text, with the descriptive rules.
- In the `description` of a skill, keep the name and the trigger phrases of the skill.
  Do not change these quoted phrases. Write the other text of the description with the
  rules.
- A prompt for a different agent must make sense alone, because that agent does not see
  your conversation.

#### Documents and artifacts

- Start each section with its primary point.
- Use headings as key words.
- Give each technical noun that a reader possibly does not know in a "Words used here"
  list. Use one line for each word.
- Use a table to compare items. Use a list for steps and alternatives.

#### Commit messages and pull requests

- Write the subject line of a commit in the imperative, for example "Add the linter".
- Write the body as descriptive text.

### Part 4: Examine your text

1. Run the linter: `python check_writing.py FILE`. The linter is in the `scripts` folder of
   the `improve-writing` skill. The linter finds the problems that a script can measure.
2. To examine words against the STE dictionary, get the standard. The standard is free
   from <https://www.asd-ste100.org>. Then give the linter your copy:
   `--dictionary PATH`. The path can be the PDF file or a text file of the PDF.
3. Read the text again for the rules that a script cannot measure. Examples are one topic
   in each sentence, the local-references rule, and accurate facts.

The `/improve-writing` skill does these three steps and writes the text again.
