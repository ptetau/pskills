# DES-writing-style · How pdlc writes

Status: agreed · Default: yes · Ask at init: yes

## Question

How should pdlc write specs, intents and change specs?

- A · plain and short (recommended): short sentences, simple words, no jargon. Anyone on the
  team can read a spec in a minute, and the agents follow plain rules more reliably.
- B · your own style guide: point pdlc at the guide you already use.

## Rule

- Short sentences. Simple words. No jargon unless the project uses it.
- Say what to do, not only what to avoid.
- A list is better than a paragraph when there are three or more items.
- If a sentence needs rereading, rewrite it.
